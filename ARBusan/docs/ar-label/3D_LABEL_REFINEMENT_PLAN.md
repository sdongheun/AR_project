# ARBusan 3D Label Refinement Plan

`EDGE_MARKER_RULES.md`의 하위 계획 문서다. 3D 라벨/마커의 장기 방향을 정리하며, 기존 외벽 부착형 로직은 교훈만 짧게 남긴다.

## 1. 현재 결론

기존 방식은 `VWorld Polygon 외벽 후보점 -> WGS84/RealityKit Anchor -> 구체/텍스트 라벨`이었다. 길 건너 건물에서는 동작을 확인했지만, 가까운 건물/도심/위치 흔들림 상황에서 구체가 이동하거나 라벨 가독성이 낮아지는 문제가 있었다.

이후 `대표/정문 마커 좌표` 방식도 검토했지만, 부산 전체 관광지를 사람이 직접 보정하기 어렵고 자동 정문 추정도 도심 환경에서 불안정하다. 따라서 새 기본 방향은 `TMAP 보행자 경로 마지막 도착 좌표 -> WGS84/RealityKit 3D 마커`다.

앞으로의 기본 방향은 아래처럼 역할을 분리한다.

```text
3D 마커:
    TMAP 보행자 경로의 마지막 도착 지점에 고정되는 지도 마커 역할
    높이는 우선 지면 기준 1.7m로 고정하고, 실외 검증 후 1.5~1.8m 범위에서 조정

길찾기 화살표:
    현재 위치에서 목적지까지 이동 방향을 안내

정보 표시:
    최종 방향은 3D 마커 hit/tap으로 관광지 정보 표시

edge marker:
    전환 전/원거리 대상의 방향을 안내
```

즉, 3D 텍스트를 건물 외벽에 직접 붙이는 것을 메인 UX로 보지 않는다. 3D는 “길찾기상 도착해야 할 지점”을 보여주고, 정확한 건물 방향은 경로 화살표와 마커 탭 정보가 담당한다.

## 2. 유지할 기존 자산

- TourAPI/목업 POI 후보 구조
- TMAP 보행자 경로에서 마지막 도착 좌표를 추출하는 구조
- VWorld Polygon 조회/건물형 판단은 보조 검증 자산으로 보존
- WGS84 Anchor + RealityKit Entity 표시 구조
- 거리별 3D 표시 범위: `0~120m 3D`, `120m~1km 2D/edge 중심`
- 120m 생성 / 140m 삭제 hysteresis
- 여러 POI의 WGS84 Anchor를 동시에 유지하는 구조
- RealityKit Entity hit-test와 탭 확대 구조
- stable origin 기반 위치 안정화

## 3. 축소할 기존 규칙

- `heading ray가 외벽과 교차하면 교차점, 아니면 가장 가까운 외벽점`은 더 이상 기본 배치 규칙으로 쓰지 않는다.
- 외벽 후보점/nearest facade/카메라 ray 계산은 디버그나 fallback 참고값으로만 남긴다.
- Scene Semantics와 OCR은 현재 메인 로직에서 제외한다.
- 3D 텍스트를 외벽에 직접 붙이는 UX는 보류한다.
- VWorld Polygon 기반 대표/정문 자동 계산은 MVP 기본 경로에서 제외한다.

## 4. 앞으로의 3D 로직

```text
TourAPI 또는 목업 POI
-> 현재 위치에서 TMAP 보행자 경로 요청
-> 응답 경로의 마지막 도착 좌표 추출
-> WGS84 Anchor 생성
-> 3D 마커 표시
-> 경로 화살표로 이동 방향 안내
-> 3D 마커 hit/tap 시 관광지 정보 표시
```

부산 전체 관광지를 사람이 하나씩 입력하지 않는다. 기본은 TMAP 도착 좌표 자동 추출이고, 수동 좌표는 TMAP 결과가 이상한 관광지에만 보정값으로 추가한다.

3D 마커 좌표 우선순위:

1. TMAP 보행자 경로 마지막 도착 좌표
2. 캐시된 TMAP 도착 좌표
3. 수동 `preferredMarkerCoordinate`/`entranceCoordinate`
4. TourAPI/목업 POI 좌표 fallback

품질 등급:

```text
tmapArrival:
    TMAP 보행자 경로 마지막 도착 좌표. MVP 기본값.

cachedArrival:
    이전에 저장한 TMAP 도착 좌표.

manual:
    사람이 지정한 보정 좌표.

poiFallback:
    TMAP 호출 실패 또는 키 없음으로 POI 좌표 사용.

edgeOnly:
    3D 마커보다 2D/edge 안내가 더 안전한 대상.
```

목표 비율은 자동 `80~90%`, 수동 보정 `10~20%`다.

중요 규칙:

- 마커는 같은 목적지 안에서 계속 움직이지 않는다.
- 사용자가 좌우로 이동하거나 heading이 흔들려도 마커가 건물 밖으로 튀면 안 된다.
- 3D 마커는 도착 지점 식별 보조이고, 정확한 이동 방향은 TMAP 경로 화살표로 처리한다.

## 5. 비건물형 POI 로직

비건물형도 같은 TMAP 도착점 기반 흐름을 사용한다.

예:

- 바다
- 공원
- 광장
- 해변
- 전망 포인트

처리 방식:

```text
TourAPI POI
-> TMAP 보행자 경로 마지막 도착 좌표
-> 해당 좌표에 3D 마커 후보
-> 원거리 또는 화면 밖이면 2D/edge marker 중심
```

비건물형은 건물 외벽이 없으므로 외벽/정문 계산을 하지 않는다. TMAP 결과가 없으면 TourAPI POI 좌표 fallback을 사용한다.

## 6. 방향 안내 규칙

사용자 heading과 대상 bearing 차이로 방향 문구를 만든다.

```text
정면: -25도 ~ +25도
왼쪽 앞/오른쪽 앞: 25도 ~ 75도
왼쪽/오른쪽: 75도 ~ 115도
왼쪽 뒤/오른쪽 뒤: 115도 ~ 155도
뒤쪽: 155도 ~ 180도
```

2D 카드 예시:

```text
후참잘
31m / 오른쪽 앞
```

방향 문구는 smoothing을 적용해 `왼쪽 앞`과 `왼쪽` 사이가 빠르게 깜빡이지 않게 한다.
