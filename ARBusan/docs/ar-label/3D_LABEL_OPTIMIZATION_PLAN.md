# ARBusan 3D Marker & Route Arrow MVP Plan

이 문서는 길찾기 MVP의 핵심 두 요소를 정리한다.

1. `3D 구체/마커`
2. `길찾기 회전 안내 화살표`

기존 `VWorld Polygon 외벽점`, `nearest facade`, `heading ray 교차점` 기반 구체 배치는 MVP에서 삭제한다. 남기는 경우에도 디버그/검증용 참고값일 뿐, 실제 길찾기 마커 위치를 결정하지 않는다.

## 1. 3D 구체/마커 MVP

### 목표

3D 구체는 `TMAP 보행자 길찾기 마지막 도착 좌표` 위에 고정한다. 길찾기 모드에서는 선택 목적지 1개만 표시하고, 평소 둘러보기 모드에서는 근처 POI들의 구체도 같은 기준을 사용한다.

사용자가 이동하거나 좌우로 바라봐도 구체가 사용자를 따라오면 안 된다. 구체는 한 좌표에 고정되어 있어야 하고, 사용자는 그 구체 주위를 둘러볼 수 있어야 한다.

### 삭제할 기존 로직

아래 로직은 길찾기 MVP에서 제거한다.

- 건물 Polygon 외곽선 위에 구체를 붙이는 방식
- 내 위치에서 가장 가까운 Polygon 외벽점 선택
- heading ray가 Polygon과 교차하는 지점 선택
- 교차점이 없으면 가장 가까운 외벽점 선택
- 사용자 위치/heading 변화에 따라 같은 POI의 구체 위치를 재계산하는 방식

이 로직들은 “왜 실패했는지” 기록만 남긴다. 길찾기/둘러보기 모드의 실제 구체 위치에는 쓰지 않는다.

### 새 기준

```text
사용자 현재 위치
-> 목적지 POI 선택
-> TMAP 보행자 길찾기 요청
-> 응답 경로의 마지막 도착 좌표 추출
-> 그 좌표에 WGS84/RealityKit 3D 마커 생성
```

좌표 우선순위:

1. TMAP 보행자 경로 마지막 도착 좌표
2. 캐시된 TMAP 도착 좌표
3. TMAP 실패 시 POI 좌표 fallback

수동 `preferredMarkerCoordinate`, `entranceCoordinate`, VWorld Polygon 기반 좌표는 이번 MVP 기본값에서 제외한다. 나중에 TMAP 결과가 명백히 틀린 장소만 예외 보정으로 검토한다.

### 완료 기준

- 길찾기 모드에서 선택 목적지 1개만 3D 구체가 뜬다.
- 둘러보기 모드에서 근처 POI 구체도 TMAP 마지막 도착 좌표에 뜬다.
- 구체 좌표 출처 로그가 `TMAP 도착 좌표`로 나온다.
- 내가 이동하거나 카메라 방향을 바꿔도 구체가 건물 외벽을 따라 움직이지 않는다.
- 목적지를 다시 선택하지 않는 한 같은 구체가 같은 도착 좌표에 고정된다.
- TMAP 실패 시에만 POI 좌표 fallback임을 로그로 명확히 표시한다.

### 필수 로그

기본 UI에서 아래 항목을 바로 볼 수 있어야 한다.

- 현재 위치 좌표
- 목적지 POI 좌표
- TMAP 마지막 도착 좌표
- 실제 3D 구체 생성 좌표
- 구체 좌표 출처: `TMAP 도착 좌표`, `cached TMAP`, `POI fallback`
- RealityKit anchor 생성/업데이트/제거 상태

## 2. 길찾기 회전 안내 화살표 MVP

### 목표

화살표는 TMAP 경로에서 방향이 크게 꺾이는 지점의 `정확한 좌표`에 꽂지 않는다.

대신 사용자가 꺾임 지점 근처 바운더리 안에 들어오면, 현재 카메라/진행 방향 기준 전방에 큰 3D 화살표를 띄운다. 목적은 “저 좌표에 화살표가 있다”가 아니라 “지금 여기서 왼쪽/오른쪽으로 꺾어야 한다”를 안정적으로 전달하는 것이다.

기본 규칙:

```text
TMAP 경로 수신
-> 직진 방향 대비 45도 이상 꺾이는 지점을 turn point로 추출
-> 사용자가 turn point 반경 5~15m 안에 들어오면 turn 안내 활성화
-> 화살표는 turn point 좌표에 직접 고정하지 않음
-> 현재 카메라/진행 방향 기준 전방 2~4m, 기기 높이 근처에 표시
-> 좌회전/우회전/뒤돌기/직진 유지 방향만 명확히 표현
-> turn point를 지나거나 다음 segment 방향으로 정렬되면 화살표 제거
```

### 현재 문제

이전 방식의 “화살표 N개 생성”은 AppState에서 경로 좌표 기반 AR 배열을 만들었다는 뜻이었다. 하지만 실제 화면에서는 아래 문제가 반복됐다.

- TMAP 경로 좌표가 잘못 들어왔다.
- AR 좌표 변환이 현재 위치 기준과 맞지 않는다.
- 화살표가 카메라 뒤쪽 또는 시야 밖에 있었다.
- RealityKit 엔티티는 생성됐지만 높이 y값이 바닥 아래였다.
- 화살표 크기/색/방향이 작거나 어두워 눈에 안 띈다.
- ARKit 바닥 raycast가 지면을 못 잡아 높이 보정이 실패했다.

따라서 바닥 전체 경로 화살표와 turn point 좌표 정밀 고정은 MVP에서 제외한다.

### 검증 순서

아래 순서로 안내 안정성을 검증한다.

1. TMAP 경로 수신 검증
   - route 좌표 개수
   - 전체 경로 길이
   - 첫 좌표/마지막 좌표
   - 마지막 좌표가 목적지 도착점과 일치하는지 확인

2. 회전 지점 추출 검증
   - 직진 대비 45도 이상 꺾이는 turn point 개수
   - 좌회전/우회전 방향
   - 현재 위치와 turn point 거리
   - turn boundary 진입/이탈 상태

3. 전방 화살표 렌더링 검증
   - RealityKit 화살표 엔티티 생성 개수
   - 현재 카메라/진행 방향 기준 전방 거리
   - 기기 높이 기준 y값
   - 화면에서 충분히 큰 크기와 밝은 색상

4. 안내 종료 검증
   - turn point를 지나면 화살표가 사라지는지 확인
   - 다음 segment 방향으로 정렬되면 안내가 과하게 유지되지 않는지 확인
   - 목적지 5~15m 이내에서는 길안내 종료 상태로 전환

### 완료 기준

- 목적지 선택 후 TMAP 경로 좌표가 정상 수신된다.
- 직진 대비 45도 이상 꺾이는 지점이 turn point로 계산된다.
- 사용자가 turn point 바운더리 안에 들어올 때만 큰 3D 화살표가 뜬다.
- 화살표는 turn point 좌표에 직접 꽂히지 않고, 사용자 전방 2~4m에 표시된다.
- 화살표 높이는 바닥 기준이 아니라 기기 높이 근처다.
- turn point를 지나거나 방향이 정렬되면 화살표가 사라진다.
- 목적지 5~15m 이내에서는 2D 라벨을 숨기고 도착 3D 대형 핀 상태로 전환한다.
- 로그에서 계산 단계와 RealityKit 렌더 단계가 분리되어 확인된다.

### 필수 로그

기본 UI에서 아래 항목을 바로 볼 수 있어야 한다.

- 선택 목적지명
- TMAP route 좌표 개수
- route 전체 길이
- turn point 개수
- 현재 활성 turn point 이름/거리/좌우 방향
- turn boundary 진입/이탈 상태
- 전방 화살표 표시 여부
- 전방 화살표 거리/y값
- RealityKit 엔티티 생성 개수
- 도착 거리와 도착 판정 기준: `5~15m`

- [x] 선택 목적지 1개만 3D 구체 생성
- [x] 둘러보기 구체 좌표도 TMAP 마지막 도착 좌표로 고정
- [x] 길찾기 구체 좌표를 TMAP 마지막 도착 좌표로 고정
- [x] 구체 좌표 출처 로그 추가
- [ ] 실외에서 구체가 내 위치를 따라 움직이지 않는지 확인
