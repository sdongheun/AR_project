# ARBusan 3D Marker & Route Arrow MVP Plan

이 문서는 길찾기 MVP의 핵심 두 요소를 정리한다.

1. `3D 구체/마커`
2. `길찾기 바닥 화살표`

기존 `VWorld Polygon 외벽점`, `nearest facade`, `heading ray 교차점` 기반 구체 배치는 MVP에서 삭제한다. 남기는 경우에도 디버그/검증용 참고값일 뿐, 실제 길찾기 마커 위치를 결정하지 않는다.

## 1. 3D 구체/마커 MVP

### 목표

3D 구체는 `TMAP 보행자 길찾기 마지막 도착 좌표` 위에 고정한다. 길찾기 모드에서는 선택 목적지 1개만 표시하고, 평소 둘러보기 모드에서는 근처 POI들의 구체도 같은 기준을 사용한다.

사용자가 이동하거나 좌우로 바라봐도 구체가 사용자를 따라오면 안 된다. 구체는 한 좌표에 고정되어 있어야 하고, 사용자는 그 구체 주위를 둘러볼 수 있어야 한다.

### 삭제할 기존 로직

아래 로직은 길찾기 MVP에서 제거한다.

- 건물 Polygon 외곽선 위에 구체를 붙이는 방식
- 내 위치에서 가장 가까운 Polygon 외벽점 선택
- heading ray가 Polygon과 교차하는 지점 선택
- 교차점이 없으면 가장 가까운 외벽점 선택
- 사용자 위치/heading 변화에 따라 같은 POI의 구체 위치를 재계산하는 방식

이 로직들은 “왜 실패했는지” 기록만 남긴다. 길찾기/둘러보기 모드의 실제 구체 위치에는 쓰지 않는다.

### 새 기준

```text
사용자 현재 위치
-> 목적지 POI 선택
-> TMAP 보행자 길찾기 요청
-> 응답 경로의 마지막 도착 좌표 추출
-> 그 좌표에 WGS84/RealityKit 3D 마커 생성
```

좌표 우선순위:

1. TMAP 보행자 경로 마지막 도착 좌표
2. 캐시된 TMAP 도착 좌표
3. TMAP 실패 시 POI 좌표 fallback

수동 `preferredMarkerCoordinate`, `entranceCoordinate`, VWorld Polygon 기반 좌표는 이번 MVP 기본값에서 제외한다. 나중에 TMAP 결과가 명백히 틀린 장소만 예외 보정으로 검토한다.

### 완료 기준

- 길찾기 모드에서 선택 목적지 1개만 3D 구체가 뜬다.
- 둘러보기 모드에서 근처 POI 구체도 TMAP 마지막 도착 좌표에 뜬다.
- 구체 좌표 출처 로그가 `TMAP 도착 좌표`로 나온다.
- 내가 이동하거나 카메라 방향을 바꿔도 구체가 건물 외벽을 따라 움직이지 않는다.
- 목적지를 다시 선택하지 않는 한 같은 구체가 같은 도착 좌표에 고정된다.
- TMAP 실패 시에만 POI 좌표 fallback임을 로그로 명확히 표시한다.

### 필수 로그

기본 UI에서 아래 항목을 바로 볼 수 있어야 한다.

- 현재 위치 좌표
- 목적지 POI 좌표
- TMAP 마지막 도착 좌표
- 실제 3D 구체 생성 좌표
- 구체 좌표 출처: `TMAP 도착 좌표`, `cached TMAP`, `POI fallback`
- RealityKit anchor 생성/업데이트/제거 상태

## 2. 길찾기 바닥 화살표 MVP

### 목표

화살표는 현재 위치에서 목적지까지의 TMAP 경로를 따라 지면 위에 표시되어야 한다.

화살표가 공중에 떠 있거나, 바닥 아래에 박혀서 보이지 않거나, 내가 볼 수 없는 엉뚱한 위치에 생성되면 실패다.

### 현재 문제

로그상 “화살표 N개 생성”은 AppState에서 AR 좌표 배열을 만들었다는 뜻이다. 하지만 실제 화면에 보이지 않으면 아래 중 하나다.

- TMAP 경로 좌표가 잘못 들어왔다.
- AR 좌표 변환이 현재 위치 기준과 맞지 않는다.
- 화살표가 카메라 뒤쪽 또는 시야 밖에 있다.
- RealityKit 엔티티는 생성됐지만 높이 y값이 바닥 아래다.
- 화살표 크기/색/방향이 작거나 어두워 눈에 안 띈다.
- ARKit 바닥 raycast가 지면을 못 잡아 높이 보정이 실패했다.

### 검증 순서

한 번에 UX까지 완성하지 않는다. 아래 순서로 원인을 분리한다.

1. TMAP 경로 수신 검증
   - route 좌표 개수
   - 전체 경로 길이
   - 첫 좌표/마지막 좌표
   - 마지막 좌표가 목적지 도착점과 일치하는지 확인

2. AR 좌표 변환 검증
   - 각 화살표의 east/north/yaw/y값 로그
   - 첫 3~5개 화살표만 로그에 표시
   - 현재 위치 기준 앞쪽인지, 뒤쪽인지 표시

3. 렌더링 검증
   - RealityKit 화살표 엔티티 생성 개수
   - 실제 scene anchor 추가 여부
   - 바닥 raycast 감지 여부
   - 감지된 `groundY`

4. 테스트용 과장 표시
   - 화살표 색상을 밝게 표시
   - 크기를 임시로 키움
   - 바닥보다 `0.2~0.4m` 위에 임시 표시
   - 첫 번째 화살표 위치에 임시 디버그 구체를 함께 표시

5. 지면 정합성 조정
   - 화살표가 보이는 것을 확인한 뒤 바닥 높이로 낮춘다.
   - raycast가 잡히면 `groundY + 소폭 offset`
   - raycast가 안 잡히면 fallback 높이를 로그로 표시한다.

### 완료 기준

- 목적지 선택 후 TMAP 경로 좌표가 정상 수신된다.
- 화살표가 한 개가 아니라 경로를 따라 여러 개 생성된다.
- 화살표는 사용자가 실제로 보는 지면 위에 보인다.
- 바닥에 박혀 보이지 않는 상태가 아니어야 한다.
- 공중에 떠다니는 상태가 아니어야 한다.
- 로그에서 계산 단계와 RealityKit 렌더 단계가 분리되어 확인된다.

### 필수 로그

기본 UI에서 아래 항목을 바로 볼 수 있어야 한다.

- 선택 목적지명
- TMAP route 좌표 개수
- route 전체 길이
- 생성된 화살표 개수
- 첫 3~5개 화살표의 거리/east/north/yaw/y
- RealityKit 엔티티 생성 개수
- 바닥 raycast 상태: `감지`, `미감지`
- 적용된 화살표 높이 기준: `groundY`, `fallbackY`
