# ARBusan AR MVP Direction

이 문서는 공모전 MVP 기준을 다시 고정하기 위한 현재 활성 방향이다. 이전 상시 카메라/3D 외벽 부착형 실험은 보존하되, 기본 UX 기준으로 삼지 않는다.

## 1. 결론

MVP는 `2D 지도 기반 관광지 탐색 + 필요할 때만 카메라 AR 길찾기`로 간다.

정밀한 3D 오브젝트를 실제 건물/바닥 좌표에 완벽히 붙이는 방식은 한국 테스트 환경에서 안정성이 부족했다. 따라서 AR은 “정확히 붙이는 기술”보다 “사용자가 어느 방향으로 가야 하는지 직관적으로 안내하는 화면”으로 제한한다.

MVP의 핵심 가치는 AR 기술 자체가 아니라 `2D 지도만 보고 방향감각을 잡기 어려운 사용자가 더 쉽게 길을 찾게 만드는 UX`다. 사용자는 정확한 좌표 오브젝트보다 “지금 어느 쪽으로 가야 하는지”, “언제 꺾어야 하는지”, “목적지 근처에 도착했는지”를 안정적으로 이해해야 한다.

따라서 위치/GPS/VPS/heading은 오차가 있다는 전제로 설계한다. 센서값이 완벽하지 않아도 사용자 경험이 무너지지 않는 구조를 우선한다.

## 2. 사용자 문제

- 일반 2D 지도는 경로를 정확히 보여주지만, 사용자가 실제 거리에서 어느 방향을 봐야 하는지 헷갈릴 수 있다.
- 도심에서는 GPS 위치가 수 m에서 수십 m까지 튈 수 있고, 건물/전파 환경 때문에 heading도 남쪽을 남동/남서처럼 잘못 읽을 수 있다.
- 좌표 하나에 3D 화살표나 핀을 정밀 고정하면 오차가 그대로 사용자에게 보이고, 오히려 신뢰도가 떨어질 수 있다.
- 사용자는 기술적 정확도보다 “지금 행동해야 할 다음 한 가지”를 명확히 받는 것이 중요하다.

## 3. 핵심 UX 흐름

```text
앱 실행
-> 일반 2D 지도 표시
-> TourAPI 관광지를 지도 핀으로 표시(현재 위치 기준 3km)
-> 사용자가 관광지 핀 선택
-> 관광지 라벨/카드 표시(사진, 정보보기, 길찾기)
-> 정보보기: 상세 정보 창으로 전환(1차 MVP는 창만 구성)
-> 길찾기: 카메라/AR 화면 실행
-> 하단 1/3에는 2D 지도/경로 기준점 표시
-> 상단 카메라에는 현재 행동을 알려주는 큰 AR 안내 표시
-> 꺾임 지점은 정밀 좌표가 아니라 바운더리 진입으로 판단
-> 도착 좌표 5~15m 이내에서는 길안내 종료
-> 도착 상태에서는 목적지 도착을 명확히 표시
```

## 4. UX 설계 원칙

- 2D 지도는 길찾기의 신뢰 기준이다.
- AR은 정밀 좌표 고정이 아니라 방향감각 보조 역할을 한다.
- 위치는 점이 아니라 권역으로 판단한다.
- heading은 각도 하나가 아니라 이동 방향, 경로 방향, 최근 안정값과 함께 판단한다.
- 센서가 불안정하면 AR 안내를 약화하고 2D 지도 안내를 강화한다.
- 사용자가 보는 화면에는 “정확한 좌표값”보다 “다음 행동”이 먼저 보여야 한다.
- 안내 문구는 `직진`, `왼쪽`, `오른쪽`, `목적지 근처`처럼 단순해야 한다.
- 길찾기 UX는 흔들림이 적고 읽기 쉬운 것이 우선이다.

## 5. 화면 구성

- 메인 화면: 일반 2D 지도와 TourAPI 관광지 핀
- 관광지 라벨/카드: 사진, 정보보기, 길찾기 버튼
- 정보보기 화면: 1차 MVP에서는 새 창 전환만 구현
- AR 길찾기 화면: 길찾기 버튼을 눌렀을 때만 카메라 실행
- 하단 지도: AR 길찾기 중에도 사용자가 경로 기준을 잃지 않도록 표시
- AR 안내판: `직진`, `오른쪽으로 이동`, `50m 후 회전` 같은 큰 안내
- 3D 회전 화살표: 꺾임 지점 좌표에 직접 꽂지 않고, 꺾임 바운더리 안에서 사용자 전방에 표시
- 도착 표시: 도착 근처에서만 강조 표시

## 6. 위치 오차 대응

- 도착은 정확한 좌표가 아니라 `5~15m 도착권역`으로 판단한다.
- 경로 이탈은 짧은 순간이 아니라 일정 거리/시간 이상 지속될 때만 판단한다.
- 꺾임 지점은 좌표 하나가 아니라 `회전 바운더리`로 처리한다.
- 위치 정확도가 낮을 때는 AR 오브젝트를 강하게 고정하지 않는다.
- 현재 위치가 튀면 최근 안정 위치를 잠시 유지해 안내가 급격히 바뀌지 않게 한다.
- 필요하면 현재 위치를 TMAP 경로선에 가깝게 보정하는 map matching 성격의 처리를 검토한다.

## 7. Heading 오차 대응

- 나침판 heading 하나만으로 좌/우 안내를 확정하지 않는다.
- 정지 상태에서는 heading 신뢰도가 낮을 수 있으므로 안내를 보수적으로 표현한다.
- 사용자가 걷고 있을 때는 최근 이동 방향을 heading보다 더 신뢰할 수 있다.
- 순간 heading 변화는 smoothing하고, 급격한 변화는 1~2초 이상 유지될 때만 반영한다.
- 방향 안내는 정밀 각도가 아니라 `정면`, `약간 왼쪽`, `왼쪽`, `오른쪽`, `뒤쪽` 같은 구간으로 표현한다.
- heading이 불안정하면 “천천히 주변을 비춰 방향을 확인하세요”처럼 사용자 행동을 유도한다.

## 8. 유지할 기능

- SwiftUI + ARKit/RealityKit 카메라 화면
- ARCore Geospatial/CoreLocation 위치 수신
- heading/pose 기반 방향 계산
- TourAPI 후보 로딩 구조
- TMAP 보행자 경로와 마지막 도착 좌표
- 2D 지도 핀/라벨 구조
- 2D 방향 라벨/edge marker
- 위치 신뢰도/경로/도착 좌표 기본 로그

## 9. 기본 비활성/보류 기능

- 건물 외벽 Polygon에 3D 구체/텍스트를 붙이는 방식
- VWorld Polygon 기반 정문/대표점 자동 계산
- matrix/polygon 디버그 마커
- Scene Semantics/OCR 기반 후보 보정
- 지면에 정확히 붙는 바닥 화살표
- 방향 전환 좌표에 3D 화살표를 정밀 고정하는 방식
- 여러 POI를 동시에 정밀 3D Anchor로 띄우는 방식

보류 기능은 삭제하지 않는다. `FeatureFlags`로 기본 비활성화하고, 필요할 때만 다시 켠다.

## 10. 성공 기준

- 공모전 시연에서 앱이 안정적으로 실행된다.
- 사용자는 2D 지도에서 3km 이내 TourAPI 관광지를 핀으로 확인할 수 있다.
- 관광지 핀을 누르면 사진/정보보기/길찾기 버튼이 있는 라벨이 뜬다.
- 카메라 화면에서는 큰 방향 안내가 흔들림 없이 읽힌다.
- 목적지 선택 후 TMAP 경로와 도착 좌표가 로그/화면에 반영된다.
- 길찾기 중에는 영상 레퍼런스처럼 진행 방향 안내가 보이고, 좌/우 회전 바운더리 안에서는 사용자 전방에 대형 방향 안내가 보인다.
- 바닥 전체를 잇는 점선/화살표는 지면 고도 차이로 어색해질 수 있어 기본 MVP에서 제외한다.
- TMAP 도착 좌표 기준 5~15m 이내에 들어오면 길안내가 종료되고 도착 핀 상태로 전환된다.
- AR 요소가 불안정할 때도 2D 지도/방향 라벨이 길찾기 기준점을 제공한다.
- GPS나 heading이 조금 틀려도 사용자는 다음 행동을 이해할 수 있다.

## 11. 다음 구현 순서

1. 2D 지도 메인 화면으로 전환
2. TourAPI 3km 관광지 핀 표시
3. 관광지 핀 선택 카드 구현(사진, 정보보기, 길찾기)
4. 정보보기 새 창 구현
5. 길찾기 버튼에서만 AR 카메라 실행
6. TMAP 경로 기반 다음 행동 안내 문구 계산
7. 목적지 2D 방향 라벨/edge marker 정리
8. 좌/우 회전 바운더리 진입 시 전방 3D 대형 화살표 표시
9. 도착 5~15m 길안내 종료와 3D 대형 핀 상태 구현

길찾기 로직 수정은 [`../navigation/AR_NAVIGATION_LOGIC_PLAN.md`](../navigation/AR_NAVIGATION_LOGIC_PLAN.md)를 기준으로 순차 진행한다.
