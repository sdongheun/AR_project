# ARBusan AR MVP Direction

이 문서는 공모전 MVP 기준을 다시 고정하기 위한 현재 활성 방향이다. 이전 3D 외벽 부착형 실험은 보존하되, 기본 UX 기준으로 삼지 않는다.

## 1. 결론

MVP는 `지도 기반 탐색 + 카메라 AR 방향 안내`로 간다.

정밀한 3D 오브젝트를 실제 건물/바닥에 완벽히 붙이는 방식은 한국 테스트 환경에서 안정성이 부족했다. 따라서 AR은 “정확히 붙이는 기술”보다 “사용자가 어느 방향으로 가야 하는지 직관적으로 안내하는 화면”으로 제한한다.

## 2. 핵심 UX

```text
TourAPI/목업 후보
-> 하단 반원형 지도/레이더로 주변 후보와 경로 확인
-> 사용자가 목적지 선택
-> TMAP 보행자 경로 요청
-> 카메라 화면 위에 큰 방향 안내판/화살표 표시
-> 도착 근처에서는 TMAP 마지막 도착 좌표 기준 목적지 핀 표시
```

## 3. 화면 구성

- 카메라 화면: 실제 주변을 보며 방향 안내를 받는 AR 화면
- 하단 반원형 지도/레이더: 현재 위치, heading, 경로, 주변 후보를 안정적으로 표시
- AR 안내판: “직진”, “오른쪽으로 이동”, “50m 후 회전” 같은 큰 안내
- 목적지 핀: 도착 근처에서만 강조 표시

## 4. 유지할 기능

- SwiftUI + ARKit/RealityKit 카메라 화면
- ARCore Geospatial/CoreLocation 위치 수신
- heading/pose 기반 방향 계산
- TourAPI 후보 로딩 구조
- TMAP 보행자 경로와 마지막 도착 좌표
- 하단 반원형 2D 레이더
- 위치 신뢰도/경로/도착 좌표 기본 로그

## 5. 기본 비활성/보류 기능

- 건물 외벽 Polygon에 3D 구체/텍스트를 붙이는 방식
- VWorld Polygon 기반 정문/대표점 자동 계산
- matrix/polygon 디버그 마커
- Scene Semantics/OCR 기반 후보 보정
- 지면에 정확히 붙는 바닥 화살표
- 여러 POI를 동시에 정밀 3D Anchor로 띄우는 방식

보류 기능은 삭제하지 않는다. `FeatureFlags`로 기본 비활성화하고, 필요할 때만 다시 켠다.

## 6. 성공 기준

- 공모전 시연에서 앱이 안정적으로 실행된다.
- 사용자는 하단 지도/레이더로 주변 후보와 목적지를 이해할 수 있다.
- 카메라 화면에서는 큰 방향 안내가 흔들림 없이 읽힌다.
- 목적지 선택 후 TMAP 경로와 도착 좌표가 로그/화면에 반영된다.
- AR 요소가 불안정할 때도 하단 지도/레이더가 길찾기 기준점을 제공한다.

## 7. 다음 구현 순서

1. FeatureFlags로 이전 실험 UI를 기본 숨김 처리
2. 하단 반원형 지도/레이더를 MVP 메인 UI로 정리
3. TMAP 경로 기반 다음 행동 안내 문구 계산
4. 카메라 화면 위 큰 AR 방향 안내판 구현
5. 도착 근처 목적지 핀 표시 방식 재정의
6. TourAPI 부산 후보 재연결
