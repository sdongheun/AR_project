# 도착 AR 포토존 + 스탬프 MVP

> 목적: 이 프로젝트의 **AR 정체성**을 책임지는 핵심 체험. 길찾기/인식은 "데려다주는" 보조이고,
> **도착 지점(근거리)에서의 공간 AR 촬영 + 스탬프 수집**이 와우·차별·완성도를 담당한다.
>
> 핵심 명제: *AR은 가까울 때(VIO가 앵커를 단단히 잡을 때) 견고하다.* 그래서 진짜 3D AR은
> **도착 근거리에만** 몰아넣고, 원거리(길찾기·인식)는 가벼운 2D로 둔다.
>
> 관련 결정 맥락: 제품 방향 재정렬(`docs/navigation/RIBBON_ARROW_NATURALNESS_SCENARIOS.md` §0),
> 길안내 = 2D 목적지 표시 + 근거리 3D 핀.

---

## 0. 설계 원칙 (왜 이 형태인가)

1. **효과 기반 공간 AR (에셋 기반 아님)**: 커스텀 캐릭터/마스코트를 그리지 않는다.
   **3D 타이포(장소명) + 빛/발광 효과**로 진짜 3D를 만든다 → 취향을 안 타고(촌스러움 회피),
   아트 부담이 거의 없으며, 인스타에서 잘 먹힌다.
2. **근거리 = 견고**: 도착 지점은 VIO가 앵커를 단단히 잡아 3D가 흔들리지 않는다.
   (원거리 월드 고정은 GPS/heading 때문에 깨지므로 안 함.)
3. **단순 2D 프레임은 AR이 아니다 / 커스텀 3D는 취향 리스크다** → 그 사이의 **"공간 타이포+빛"** 이 정답.
4. **정직한 강등**: 트래킹 불안정(§4-B)이면 3D를 숨기고 안내 텍스트로.

## 1. 사용자 흐름 (MVP)

```
① 도달        길찾기 또는 근접으로 POI 근처 도달
                → 기존 3D 빨간 도착 핀 표시 (이미 구현)
② 잠금 해제    핀을 터치 → "사진 촬영" 모드 진입(잠금 해제)
                → 관광지 이름의 3D 타이포(공간 AR) 등장
③ 구도        걸어서 각도 + 핀치(크기)·두 손가락 회전으로 구도 조정
④ 촬영        촬영 버튼 → ARView 화면 캡처
⑤ 스탬프      촬영 성공 시 해당 관광지 스탬프 획득 → 컬렉션에 추가
```

- **잠금 조건**: 도착 핀이 떠 있는 상태(= POI 근거리, `arrivalPin != nil`)에서만 촬영 가능.
  멀리서는 비활성(2D 목적지 표시만).
- **재방문**: 이미 스탬프가 있어도 사진은 다시 찍을 수 있음(스탬프는 중복 추가 안 함, 사진은 별도 저장).

---

## 2. AR 구성 (촬영 화면)

| 요소 | 내용 | 비고 |
|---|---|---|
| **3D 장소 타이포** | 관광지 이름 입체 글자가 공간에 떠 있음 | `generateText`로 코드 생성(아트 0) |
| **빛/발광 효과** | 발광 재질 + 은은한 애니메이션(회전/펄스/플로팅) | 모델링 없이 효과로 |
| **(옵션) 명소 시그니처** | 대표 1~2곳만: 광안대교=불꽃, 해운대=물결 등 | 후속/스트레치 |
| **촬영 UI** | 셔터 버튼, 닫기, (후속)크기 슬라이더 | 최소 셔터+닫기 |

- 글자는 **근거리 월드 앵커**에 배치(한 번 놓고 VIO가 고정) → 걸어 돌면 원근이 바뀜(진짜 AR).

---

## 3. 인터랙션 (구도 조절)

| 조절 | 입력 | 방식 |
|---|---|---|
| **각도/시점** | 사용자가 **걸어서** 돈다 | 월드 고정이라 자동(핵심 매력) |
| **크기** | 핀치(두 손가락) | `entity.scale` |
| **회전** | 두 손가락 회전 | Y축 회전 |
| **위치(후속)** | 한 손가락 드래그 | 평면 OFF 유지 → 카메라 앞 평면 이동(커스텀) |

- **평면 감지(planeDetection)는 OFF 유지**(발열). 글자는 **카메라 앞 고정 거리**에 배치하고 걸어서 각도.
  바닥 "딱 붙음"이 꼭 필요한 명소만 도착 모드 한정으로 평면 잠깐 ON(옵션).

---

## 4. 스탬프 시스템

- **획득 조건**: 포토존에서 **촬영 성공** 시 그 POI 스탬프 1개 획득(중복 추가 안 함).
- **저장**: 영구 저장(SwiftData `TourismSpotEntity` 활용 후보 — 방문/스탬프 플래그·시각).
- **표시**: 기록 화면(`CollectionBookView`)에서 스탬프 보유 여부·획득 시각, (후속)촬영 사진 썸네일.
- **스탬프 비주얼**: **미니멀 2D**(여권 도장/라인아트 느낌, 장소명·날짜) — 취향 안 타게. 캐릭터 아님.
- **동기부여(후속)**: 코스/미션("부산 5대 명소"), 진행도, 공유.

---

## 5. 촬영 / 저장 / 공유

- **촬영**: `ARView` 스냅샷 → 사진(3D 타이포가 합성된 실제 장면).
- **저장**: 사진 앨범 저장 + (후속)앱 내 기록.
- **공유**: 표준 공유 시트(인스타 등). 미니멀 워터마크/장소·날짜 오버레이는 후속.

---

## 6. MVP 범위 (IN / OUT)

**IN (이번 스파이크 — 검증 목표)**
- 도착 핀 터치 → 포토존 진입(잠금 해제)
- 관광지 **3D 타이포 배치**(근거리 월드 앵커)
- **핀치(크기) + 회전**
- **촬영 → 사진 저장**
- **스탬프 1개 획득 + 기록 반영**

**OUT (후속)**
- 위치 드래그 이동(평면/커스텀)
- 빛/파티클 고도화, **명소 시그니처 효과**
- 코스/미션·진행도, 사진 썸네일 갤러리, 워터마크
- 커스텀 `.usdz` 명소 한정 3D

---

## 7. 합격 기준 (실기기)

1. 도착 핀 터치 → 3D 글자가 **공간에 안정적으로** 뜬다(걸어 돌아도 제자리, 안 흔들림).
2. 핀치/회전이 **자연스럽게** 동작한다.
3. 촬영 결과가 **인스타 올릴 만큼** 보기 좋다(글자 가독·구도).
4. 촬영 시 **스탬프가 1회** 추가되고 기록에 보인다.
5. **유치하지 않다**(타이포/빛 기반, 캐릭터 없음).

---

## 8. 재사용 vs 신규

| 구분 | 항목 |
|---|---|
| **재사용** | 도착 3D 핀(`arrivalPin`/`ARSessionViewController`), `generateText`(핀 이름 라벨), 빌보드/스무딩, `CollectionBookView`, `ARView` |
| **신규** | 포토존 모드 진입(핀 탭), 3D 타이포 엔티티+제스처, 캡처, 스탬프 저장/획득 로직 |

---

## 9. 기술 메모 / 제약

- **iOS 17 호환**: `generateText`/`generateBox`/`generateSphere` + 발광 재질 + 간단 애니메이션만 사용
  (파티클 미지원 OS면 작은 발광 구 다수 + 애니메이션으로 대체).
- **제스처**: `ModelEntity` + `generateCollisionShapes` → 핀치/회전. 평면 의존 이동은 OFF.
- **발열**: 포토존은 단발성 근거리 체험이라 비용 작음. 평면 감지는 켜더라도 모드 한정.
- **캡처**: `ARView.snapshot(saveToHDR:completion:)`.

---

## 10. 후속 로드맵

1. **[이번] 포토존 스파이크**: 핀 탭 → 3D 타이포 + 핀치/회전 + 캡처 + 스탬프.
2. 빛/애니메이션 다듬기, 위치 드래그.
3. 명소 시그니처 효과(대표 1~2곳).
4. 코스/미션·진행도·갤러리·공유 워터마크.

> 각 단계는 실기기 실측으로 "유치하지 않고 인스타 가능"을 기준으로 튜닝한다.
