# ARBusan Haeundae TourAPI Indoor Debug Plan

이 문서는 부산 해운대구 TourAPI POI를 기준으로 실내 디버그 테스트를 진행하기 위한 규칙이다. 목적은 VPS/실제 위치 정확도 검증이 아니라, TourAPI POI 좌표가 들어왔을 때 앱의 Polygon 매칭, 건물형/비건물형 분기, 라벨 위치 계산이 의도대로 동작하는지 확인하는 것이다.

## 1. 테스트 목적

- 최종 서비스 데이터인 TourAPI POI를 기준으로 계산 로직을 검증한다.
- 사용자가 특정 가상 위치에 있다고 가정했을 때, POI 구체/라벨이 의도한 위치에 계산되는지 확인한다.
- 건물형 POI는 VWorld Polygon을 찾아 외벽 기준 라벨을 계산한다.
- 비건물형 POI는 Polygon이 없거나 부적합할 때 TourAPI 좌표점 기준으로 처리한다.
- 실내 디버그 성공을 실제 AR 정합 성공으로 보지 않는다. 실제 정합은 추후 VPS 지원 야외 장소에서 별도 검증한다.

## 2. 대상 지역

- 1차 대상: 부산광역시 해운대구
- TourAPI 지역 코드:
  - `areaCd=26`
  - `signguCd=26350`
- 해운대구를 먼저 선택하는 이유:
  - 해수욕장/공원/해변 같은 비건물형 관광지가 있다.
  - 전시관/시설/상업 건물형 POI가 섞여 있다.
  - 관광 밀도가 높아 1km 후보 필터, 다중 후보, 화면 안/밖 마커 검증에 적합하다.

## 3. 샘플 선정 규칙

TourAPI에서 해운대구 POI를 가져온 뒤, 아래 그룹이 최소 1개 이상 포함되도록 고정 샘플을 만든다.

### 3.1 건물형 샘플

조건:
- POI 좌표가 건물 내부 또는 건물 중심 근처에 있다.
- VWorld Polygon 조회 시 POI를 포함하는 건물 Polygon이 나온다.
- 라벨은 가장 가까운 외벽점 또는 heading ray 교차점 기준으로 계산한다.

확인 항목:
- POI가 Polygon 내부에 포함되는가?
- 선택된 Polygon이 주변 다른 건물이 아닌 해당 POI 건물인가?
- 외벽 후보점이 Polygon boundary 또는 근거리 내부 보정 위치에 있는가?

### 3.2 비건물형 샘플

조건:
- 해수욕장, 공원, 광장, 해변, 산책로처럼 단일 건물 Polygon으로 표현하기 어렵다.
- VWorld Polygon이 없거나, POI가 Polygon 내부에 들어가지 않는다.

확인 항목:
- Polygon 없음/부적합 상태를 오류가 아니라 비건물형으로 처리하는가?
- 라벨 기준 좌표가 TourAPI POI 좌표점으로 설정되는가?
- 화면 밖이면 edge marker로 방향 안내가 가능한가?

### 3.3 애매한 샘플

조건:
- POI 좌표가 건물 입구, 도로, 경계 근처에 있을 수 있다.
- 주변에 Polygon 후보가 여러 개 나올 수 있다.

확인 항목:
- POI 포함 Polygon 우선 규칙이 적용되는가?
- POI가 어떤 Polygon에도 포함되지 않으면 가장 가까운 boundary 후보를 보조로 판단하는가?
- 너무 애매하면 비건물형/point POI로 fallback 가능한가?

## 4. 실내 디버그 입력 구조

실내 디버그에서는 실제 CoreLocation/VPS 값을 그대로 쓰지 않고, 테스트용 가상 입력을 사용한다.

필수 입력:
- `debugOrigin`: 사용자가 있다고 가정하는 위도/경도
- `debugHeading`: 사용자가 바라본다고 가정하는 방향각
- `debugTargetSpot`: 집중 확인할 TourAPI POI
- `debugMode`: 실제 센서값 대신 디버그 값을 쓸지 여부

권장 입력:
- `debugDistanceScenario`: 5m, 30m, 120m, 1km 등 거리 구간
- `debugPosePitch`: 화면 투영 확인용 pitch 값
- `debugSelectedSampleSet`: 건물형/비건물형/애매한 후보 묶음

## 5. 테스트 케이스

### 5.1 건물형 정면 테스트

가정:
- 사용자가 건물 정면 10~30m 지점에 있다.
- heading은 건물 중심 또는 정면 외벽을 향한다.

기대 결과:
- POI 포함 Polygon이 선택된다.
- 3D 후보는 해당 건물 외벽 또는 근거리 내부 보정 위치에 잡힌다.
- 화면 projection 결과가 Polygon 화면 영역 밖으로 과하게 튀지 않는다.

### 5.2 건물형 근거리 테스트

가정:
- 사용자가 건물 입구 0~5m 지점에 있다.

기대 결과:
- 구체/라벨이 외벽 앞쪽으로 과하게 돌출되지 않는다.
- 라벨 높이는 눈높이 근처로 계산된다.
- 위치 오차가 크다고 가정해도 Polygon boundary 기준을 벗어난 좌표는 최종 표시 후보에서 제외된다.

### 5.3 모서리/대각선 테스트

가정:
- 사용자가 건물 모서리 근처에서 대각선 방향으로 바라본다.

기대 결과:
- 외벽 후보가 두 변 사이에서 빠르게 왕복하지 않는다.
- 이전 안정 외벽 또는 더 명확한 교차 외벽을 유지한다.
- 로그에 선택 외벽, 교차점, 최단 외벽점이 구분되어 나온다.

### 5.4 한 화면 다중 후보 테스트

가정:
- 1km 후보 중 화면 안에 2개 이상의 POI가 들어온다.

기대 결과:
- 후보별 Polygon/point 기준이 독립적으로 계산된다.
- 화면 안 후보와 화면 밖 edge marker가 구분된다.
- 같은 화면에 여러 라벨이 있을 때 겹침/우선순위 검증을 할 수 있다.

### 5.5 비건물형 테스트

가정:
- 해수욕장/공원/해변형 POI를 선택한다.

기대 결과:
- VWorld 건물 Polygon이 없어도 실패로 끝나지 않는다.
- TourAPI POI 좌표점 기준으로 point POI 후보를 만든다.
- 3D가 부적합한 거리/상태에서는 2D 방향/거리 안내로 fallback할 수 있다.

### 5.6 반대 방향 테스트

가정:
- 사용자가 POI와 180도 반대 방향을 본다.

기대 결과:
- 화면 중앙에 해당 POI 라벨이 뜨지 않는다.
- edge marker가 화면 가장자리에서 회전 방향을 안내한다.
- 3D 후보가 있더라도 화면 투영상 뒤쪽이면 표시하지 않거나 보조 상태로 둔다.

## 6. 로그 규칙

실내 디버그 로그는 아래 순서로 읽히게 한다.

```text
디버그 모드: ON/OFF
대상 지역: 부산 해운대구
debugOrigin: 위도, 경도
debugHeading: N도
TourAPI 후보 수: N개
1km 후보 수: N개
대상 POI: 이름 / 좌표 / 거리 / 방향각
VWorld Polygon: 있음/없음 / POI 포함 여부 / 후보 개수
POI 유형: 건물형 / 비건물형 / 애매함
선택 외벽: 시작/끝/교차점/최단점
라벨 후보: 좌표 / 높이 / 거리 구간
화면 투영: 화면 안/밖 / x,y / Polygon boundary 보정 여부
최종 표시: 3D 후보 / 2D 보조 / edge marker / 숨김
```

## 7. 성공 기준

- 해운대구 TourAPI POI를 앱 후보로 넣어도 목업과 같은 계산 파이프라인을 탄다.
- 건물형 POI는 POI 포함 Polygon을 우선 선택한다.
- 비건물형 POI는 Polygon 실패를 정상 fallback으로 처리한다.
- debugOrigin/debugHeading을 바꾸면 거리, 방향각, 외벽 후보, 화면 투영 값이 예측 가능한 방향으로 바뀐다.
- 실제 VPS가 없어도 계산 로직의 실패 원인을 로그로 구분할 수 있다.

## 8. 실패 기준

- TourAPI POI가 들어오면 목업과 다른 분기 로직을 탄다.
- Polygon 없음이 곧바로 오류 또는 인식 실패로 끝난다.
- POI를 포함하지 않는 주변 건물 Polygon을 무조건 선택한다.
- debugHeading을 바꿔도 화면 투영/edge marker 변화가 예측되지 않는다.
- 실내 디버그 결과를 실제 AR 정합 성공으로 오해하게 만드는 로그가 나온다.

## 9. 구현 순서

- [ ] 해운대구 TourAPI POI 로딩을 디버그 샘플 세트로 분리한다.
- [ ] 실내 디버그용 `debugOrigin`, `debugHeading` 입력 구조를 만든다.
- [ ] 목업/해운대 TourAPI 샘플을 같은 후보 파이프라인에 태운다.
- [ ] 건물형/비건물형/애매함 분류 로그를 추가한다.
- [ ] 건물형 정면/근거리/모서리 케이스를 로그로 검증한다.
- [ ] 비건물형 point POI fallback을 검증한다.
- [ ] 화면 투영과 edge marker 동작을 해운대 샘플로 검증한다.

## 10. 보류 항목

- 실제 VPS/WGS84 정합 정확도 검증
- 실제 해운대 현장 테스트
- Terrain Anchor 재검토
- Streetscape Geometry/Depth/Occlusion 적용
- 라벨 UI 최종 디자인
