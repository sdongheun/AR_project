# ARBusan 3D Label Stability Tests

이 문서는 `../ar-label/3D_LABEL_REFINEMENT_PLAN.md`를 완료한 뒤 계속 진행할 안정화 테스트 시나리오를 정리한다. 목적은 “3D 라벨이 뜬다” 이후에, 앱 재실행/이동/위치 흔들림 같은 실제 사용 상황에서 얼마나 믿을 수 있는지 검증하는 것이다.

## 1. 테스트 목적

- 앱 시작 상태에 따라 3D 라벨이 엉뚱한 위치에 고정되는지 확인한다.
- WGS84 Anchor, ARKit pose, Geospatial 위치, heading이 흔들릴 때 라벨이 어떻게 변하는지 기록한다.
- 불안정한 상태에서는 3D 라벨을 바로 믿지 않고, 2D fallback이나 위치 안정화 상태로 전환할 기준을 찾는다.

## 2. 기본 테스트 시나리오

1. 실외에서 앱 첫 실행
   - 기대: 위치/heading이 잡힌 뒤 WGS84 Anchor가 생성되고 라벨이 건물 근처에 표시된다.

2. 실내에서 앱 실행 후 실외 이동
   - 기대: 실내의 부정확한 위치로 anchor를 확정하지 않는다.
   - 추후 개선: 위치 안정화 전에는 3D anchor 생성을 지연한다.

3. 앱을 백그라운드로 보낸 뒤 다시 진입
   - 기대: 오래된 anchor/외벽 후보가 계속 남아 엉뚱한 위치에 보이지 않는다.
   - 추후 개선: foreground 복귀 시 anchor 재요청 또는 상태 초기화.

4. 같은 위치에서 30초 유지
   - 기대: 구체/라벨이 큰 폭으로 흔들리지 않는다.
   - 기록: WGS84 좌표, CoreLocation 좌표, heading 변화량.

5. 5~10m 이동 후 같은 건물 보기
   - 기대: 라벨이 새 위치 기준으로 자연스럽게 재계산된다.
   - 기록: anchor가 갱신되는 조건이 너무 빠르거나 느리지 않은지.

6. 길 건너 15~30m 거리에서 보기
   - 기대: 라벨 높이와 크기가 읽을 수 있는 수준이다.

7. 건물 바로 앞 0~5m에서 보기
   - 기대: 라벨이 눈높이 근처에 있고 화면을 과하게 가리지 않는다.

8. 모서리/대각선에서 보기
   - 기대: 외벽 후보가 빠르게 좌우로 튀지 않는다.

## 3. 추후 안정화 기준 후보

- 위치 정확도 기준: CoreLocation horizontal accuracy가 일정 값보다 나쁘면 3D anchor 생성 지연.
- Geospatial 기준: VPS/Geospatial 좌표가 안정될 때까지 3D 라벨 약화 또는 숨김.
- heading 기준: 짧은 시간 heading 변화량이 크면 anchor 갱신 보류.
- 후보 기준: 같은 건물/외벽 후보가 일정 시간 유지될 때만 anchor 생성.
- 앱 lifecycle 기준: foreground 복귀 시 anchor/외벽 후보 캐시 재검증.

## 4. 기록할 값

- 테스트 장소와 건물명
- 내 위치와 대상까지의 거리
- CoreLocation 좌표/정확도
- ARCore Geospatial 좌표/정확도
- heading 변화량
- 선택된 외벽 후보 로그
- WGS84 Anchor 생성/갱신 로그
- 실제 눈으로 본 라벨 위치 오차
