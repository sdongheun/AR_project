# AR Navigation Logic Plan

이 문서는 메인 지도에서 `길찾기` 버튼을 누른 뒤 실행되는 AR 길찾기 로직 수정 과정을 추적한다. 목표는 바닥 전체에 화살표를 붙이는 방식이 아니라, 안정적인 `2D 방향 안내 + turn boundary 카메라 전방 3D 대형 화살표 + 도착 안내` 구조를 만드는 것이다.

핵심 전제는 `GPS/VPS 위치와 heading은 불안정할 수 있다`는 것이다. 따라서 회전 좌표나 도착 좌표에 3D 오브젝트를 정밀 고정하는 방식보다, TMAP 경로를 신뢰 기준으로 삼고 사용자가 다음 행동을 이해하게 만드는 UX를 우선한다.

## 1. 현재 기준

- 길찾기는 메인 2D 지도에서 관광지 카드를 선택한 뒤 시작한다.
- 길찾기 화면에 들어오면 카메라/AR 화면이 열린다.
- 목적지는 선택된 관광지 1개만 사용한다.
- TMAP 보행자 길찾기 응답을 기준으로 경로와 마지막 도착 좌표를 사용한다.
- 바닥 전체 경로 화살표는 MVP에서 제외한다.
- 방향 전환 지점 좌표에 화살표를 정밀 고정하지 않는다.
- 사용자가 방향 전환 지점 바운더리 안에 들어오면 turn point 좌표가 아니라 카메라 로컬 기준 사용자 전방에 큰 3D 화살표를 띄운다.
- 도착 판정은 TMAP 마지막 도착 좌표 기준 5~15m 범위로 조정한다.

## 2. 수정 목표

```text
지도 핀 선택
-> 길찾기 버튼
-> AR 길찾기 화면 진입
-> 현재 위치와 목적지로 TMAP 보행자 경로 요청
-> 목적지 방향 2D 라벨/edge marker 표시
-> 경로에서 45도 이상 꺾이는 turn point 계산
-> 사용자가 turn boundary 안에 들어오면 전방 3D 대형 화살표 표시
-> turn point 통과 또는 방향 정렬 시 화살표 제거
-> 도착 좌표 5~15m 이내 진입 시 2D 라벨 숨김
-> 도착 3D 대형 핀 표시 후 길안내 종료
```

## 3. 체크리스트

### 3.1 길찾기 진입 상태 정리

- [x] 메인 지도에서 선택한 관광지가 AR 길찾기 화면으로 정확히 전달되는지 재확인
- [x] AR 길찾기 진입 시 선택 목적지 1개만 활성화
- [x] 길찾기 모드 진입 시 기존 둘러보기/디버그 3D 마커가 남지 않도록 정리
- [x] 길찾기 종료/뒤로가기 시 route 상태와 3D 엔티티 정리
- [x] 테스트: 길찾기 버튼 클릭 시 선택한 관광지 이름이 AR 화면 목적지로 표시되는지 확인

### 3.2 TMAP 경로 요청/캐시 정리

- [x] 현재 위치와 목적지 POI 기준으로 TMAP 보행자 경로 요청
- [x] TMAP 응답의 route 좌표 개수 로그 정리
- [x] route 전체 길이와 마지막 도착 좌표 로그 정리
- [x] 경로 캐시 재사용 제거: 실내 테스트에서 위치를 바꾸면 새 경로 요청
- [x] 연타/요청 중복 방지 유지: 요청 중이거나 1.5초 이내 같은 좌표 반복 적용은 차단
- [x] TMAP 실패 시 POI 좌표 fallback을 명확히 표시
- [x] 테스트: 길찾기 시작 시 route 좌표와 마지막 도착 좌표가 로그에 표시되는지 확인

### 3.3 목적지 2D 방향 라벨/edge marker 정리

- [x] 목적지 기준 좌표를 TMAP 마지막 도착 좌표로 통일
- [x] 목적지가 화면 안에 있으면 2D 방향 라벨 표시
- [x] 목적지가 화면 밖이면 edge marker 표시
- [x] 도착 근처에서는 2D 라벨/edge marker 숨김
- [x] 테스트: 카메라 방향을 돌릴 때 목적지 방향 라벨/edge marker가 바뀌는지 확인

### 3.4 turn point 계산

- [x] TMAP route polyline에서 전후 거리 샘플 기반 bearing 계산
- [x] 전후 샘플 기준 45도 이상 꺾이는 지점을 turn point 후보로 선택
- [x] 좌회전/우회전 방향 계산
- [x] 너무 가까운 turn point 중복 제거
- [x] turn boundary 반경 기준 정의
- [x] 테스트: 로그에 turn point 후보, 좌/우 방향, 내 위치와의 거리가 표시되는지 확인

### 3.5 전방 3D 대형 화살표

- [x] 사용자가 turn boundary 안에 들어왔는지 계산
- [x] 카메라 heading이 회전 지점/다음 경로 방향을 보고 있는지 계산
- [x] 화살표를 turn point 좌표가 아니라 카메라 로컬 기준 사용자 전방 2~4m에 생성
- [x] 화살표 높이는 바닥이 아니라 기기 높이 근처로 설정
- [x] 좌회전/우회전 방향에 맞게 화면 왼쪽/오른쪽 전방으로 치우치게 배치
- [x] 낮에도 보이는 파란색 계열 대형 3D 화살표 사용
- [x] turn point 통과 또는 방향 정렬 시 화살표 제거
- [x] 테스트: 실내 테스트에서 회전 지점 근처와 올바른 시야 조건에서 큰 화살표가 보이는지 확인

### 3.6 위치 불안정 대응

- [x] 현재 위치를 점 하나가 아니라 `현재 위치 + horizontalAccuracy` 오차 원으로 판단
- [x] 오차 원이 turn boundary와 겹치면 회전 준비 상태로 인정
- [x] 현재 위치가 TMAP 경로선 근처에 있으면 가장 가까운 경로점으로 스냅한 안내 위치를 계산
- [x] 경로선에서 너무 멀면 스냅하지 않고 위치 불안정 상태로 표시
- [x] 순간 위치 튐은 최근 안정 위치를 잠시 유지해 안내가 즉시 바뀌지 않도록 처리
- [~] 테스트: 실제 인도에서 GPS가 도로 쪽으로 튀는 상황 → 실외 실측 대기. 실내는 디버그 패널 `정확도 저하 시뮬레이션` 토글 + 지도 다중 탭으로 재현

### 3.7 Heading 불안정 대응

- [x] heading 단독으로 좌/우 안내를 확정하지 않도록 상태값 정리
- [x] 걷는 중에는 최근 이동 방향을 함께 사용
- [x] heading이 흔들리면 AR 안내를 보수적으로 표시
- [x] 방향 안내는 정밀 각도 대신 `정면`, `왼쪽`, `오른쪽`, `뒤쪽` 구간으로 표현
- [~] 테스트: heading이 흔들리는 장소에서 안내가 급격히 튀지 않는지 → 실외 실측 대기

### 3.8 도착 판정/도착 핀

- [x] 현재 위치와 TMAP 마지막 도착 좌표 거리 계산(보정 위치 guidedOrigin 기준)
- [x] 도착 기준을 5~15m 범위로 적용(현재 `routeArrivalCompletionMeters = 10m`)
- [x] 도착 시 길안내 상태 종료(`routeArrowPath = nil`)
- [x] 도착 시 목적지 2D 라벨/edge marker 숨김(`arrivalPin != nil`이면 edge marker 비표시)
- [x] 도착 시 3D 대형 핀 표시(`ArrivalPinSnapshot` → `ARSessionViewController.setArrivalPin`, 3.10 주행 방향 앵커링으로 목적지 방위·기기 높이에 배치)
- [x] 도착 상태 UI 문구 표시(`navigationGuidanceIsArrivalNearby`, "도착" 배너)
- [~] 테스트: 도착 좌표 근처에서 길안내 종료 + 3D 핀 표시 → 단위 테스트(도착 핀 상태/엣지 숨김, 앵커링 좌표)는 통과, 실기기 시각 검증은 실외 대기

### 3.9 안정화/성능

- [x] route 재요청 빈도 제한(기존 debounce 유지: 1.5초/1m 이내 같은 좌표 재요청 차단)
- [x] AR 엔티티 재생성 최소화(화살표 keep 분기, 리본/도착 핀 앵커 1회 생성 후 transform만 갱신)
- [x] 동일 로그 중복 출력 제한(polygonLookupLogs 90개 cap + 네비 중 Polygon 조회 차단으로 로그 급감)
- [x] 위치 정확도가 낮을 때 3D 표시를 과감히 줄이고 2D 안내 유지(3.6/3.7 게이트: 불안정 시 리본/화살표 숨김 → 텍스트 배너)
- [x] 앱 발열이 심해지는 기능 점검: OCR·Scene Semantics·Streetscape 모두 비활성 확인. 길찾기 중 인식 파이프라인(`runRecognition`)·VWorld Polygon 자동 조회(`updateCameraDirectionCandidate`, 네트워크) 차단. 미사용 평면 감지(`planeDetection`) 제거. 카메라 영상은 기본 저해상도(`videoFormat` 최저 해상도), 디버그 패널 `고해상도 카메라` 토글로 전환 가능
- [참고] AR 카메라 VIO는 정지 중에도 매 프레임 처리되어 발열은 본질적으로 누적됨. 위 항목은 불필요한 추가 부하만 제거. VPS(ARCore Geospatial) 상시 가동이 남은 최대 레버이나 위치 정확도 트레이드오프로 보류
- [~] 테스트: 5분 이상 길찾기 화면을 켜도 과도한 발열/깜빡임이 없는지 → 실기기 대기

### 3.10 바닥 리본 + 주행 방향 앵커링 + 상단 2D 라벨 제거 (UX 전환)

레퍼런스(네이버 실내 AR 바닥 선)는 실내 VPS 기반이라 실외에 좌표 고정으로 옮기면 드리프트가 재발한다. 따라서 좌표 고정이 아닌 리본으로 느낌만 가져오되, 아래 앵커링 규칙을 반드시 지킨다. 배경/결정은 `../planning/AR_MVP_DIRECTION.md` 12절.

**3D 오브젝트 앵커링 규칙 (필수 · 리본과 기존 회전 chevron 모두 적용)**

- 카메라 시선(pitch/yaw)을 따라 떠다니면 안 된다. 사용자가 바닥을 보거나 두리번거리며 걸으면 오브젝트가 엉뚱한 곳에 뜬다.
- 대신 매 프레임 **기기의 수평 위치 + 휴대폰 높이(Y, 중력 기준)** 에서 **"내가 가는 방향(경로/이동 방위)"** 으로 전방에 배치한다.
- 자세는 **중력 정렬**(pitch/roll = 0), yaw만 경로 방위로 둔다. 화면을 위/아래로 기울여도 오브젝트는 수평·정자세를 유지한다.
- 카메라 transform에서는 **위치(높이 포함)만** 취하고 **회전은 취하지 않는다.** `AnchorEntity(.camera)` 또는 카메라 transform 회전 그대로 쓰는 방식은 금지.
- 방위→AR 월드 방향 매핑: `.gravityAndHeading`이므로 월드 −Z=북, +X=동 → 방위 θ의 전방벡터 ≈ `(sinθ, 0, −cosθ)`. 배치 = `기기수평위치 + 전방벡터·거리`, Y = `기기높이 + offset`.
- "가는 방향"은 카메라 heading이 아니라 **경로 방위(다음 안내점)** 를 기본으로, 이동 방위(`MovementDirectionTracker`)로 교차 검증한다.
- heading이 불안정하면(3.7) 절대 방위가 틀어질 수 있으므로 그때는 약화/숨김 + 텍스트 폴백.

**체크리스트**

- [x] 위 앵커링 규칙으로 배치 transform 계산 유틸 추가(`TravelDirectionAnchor`: 기기 위치+높이, 방위 yaw, 중력 정렬)
- [x] 기존 회전 chevron을 카메라 transform 앵커 → 주행 방향 앵커로 교체(매 프레임 재배치, 콘텐츠면이 사용자 향함)
- [x] 경로 방위 쪽으로 뻗는 바닥 리본 엔티티 추가(좌표 고정 아님, 주행 방향 앵커, 중력 수평 레인)
- [~] 리본이 좌·우로 휘도록 표현: v1은 다음 안내점 방위로 직선 리본(회전 자체는 chevron이 강조). 경로 폴리라인을 따라 휘는 곡선 리본은 후속 v2
- [x] 기존 큰 회전 chevron과 리본을 함께 표시(중복 없이 역할 분리)
- [x] 상단 2D 방향 라벨/edge marker 제거(네비 중 edge marker `[]`, 상단 텍스트는 도착/불안정 시만)
- [x] 3.7 불안정(좌/우 확정 불가) 시 리본 숨기고 보수 안내 텍스트 배너로 폴백(`navigationGuidanceIsConservative`)
- [x] 리본/화살표를 3.6 `GuidanceFix`/heading 신뢰 게이트로 보호(불안정 시 숨김)
- [~] 테스트: 바닥을 보거나 두리번거리며 걸어도 오브젝트가 가는 방향·기기 높이에 유지되는지 → 단위 테스트(리본 표시/도착 숨김, 앵커링 좌표) 통과, 실기기 시각 검증은 실외 대기
- [ ] (보류 Tier 2) VPS/Streetscape/평면 양호 구간에서만 진짜 지면 고정 경로 선, 저신뢰 시 리본으로 폴백

## 5. 현재 구현 메모

- 도착 기준은 TMAP 마지막 도착 좌표 기준 `10m`로 적용했다.
- 회전 지점은 TMAP route polyline에서 후보점 기준 전후 약 `6m` 샘플 bearing 차이가 `45도 이상`일 때 후보로 본다.
- 사용자가 회전 후보 `18m` 안에 들어오면 화살표를 실제 turn point 좌표가 아니라 카메라 전방 약 `3m`에 표시한다.
- 카메라 heading이 회전 지점/다음 경로 방향을 보지 않으면 boundary 안이어도 화살표를 숨긴다.
- 사용자의 heading이 다음 segment 방향과 `22도 이내`로 정렬되면 회전을 수행한 것으로 보고 화살표를 숨긴다.
- 화살표는 RealityKit `AnchorEntity(.camera)`를 사용하므로 지면 고도/raycast 영향을 받지 않는다.
- TMAP 요청 실패 또는 키 미설정 시에는 POI 중심 좌표를 도착점으로 하는 직선 fallback 경로를 만들고 로그에 `POI fallback`으로 표시한다.
- 경로 캐시 재사용은 제거했다. 실내 테스트에서 위치를 바꾸면 새 TMAP 경로를 요청하고, 같은 좌표 연타/요청 중복만 차단한다.

### 5.1 위치/heading 불안정 대응 메모 (3.6/3.7)

- 3.6/3.7 핵심 로직은 `ARBusan/Navigation/NavigationStabilizer.swift`에 AppState/UI 비의존 순수 로직으로 두고, `NavigationStabilizerTests`로 검증한다. 실외 실측과 실내 디버그가 같은 함수를 쓴다.
- AppState는 길찾기 안내 시 원시 위치 대신 `guidanceStabilizer`가 만든 보정 위치(guidedOrigin)를 도착/회전/방향 계산에 쓴다. 임계값은 `NavigationGuidanceStabilizer.Config`로 조정한다.
  - 경로선 4m 이내: 원시 위치 사용 / 4~20m: 경로선 스냅 / 20m 초과: 스냅 안 함, 위치 불안정 표시
  - 정확도 25m 초과: 위치 불안정 / 직전 안정 위치에서 15m 이상 점프 + 2초 이내: 최근 안정 위치 유지
  - turn boundary 판정은 `거리 - 오차반경 <= 18m`로 오차 원을 반영한다.
- heading은 `movementTracker`(1.5m 이상 이동 시 이동 방향 추정, 4초 staleness)와 나침반을 융합한다. 걷는 중이면 이동 방향을, 아니면 나침반을 쓰되 변화량이 12도 초과면 신뢰하지 않는다.
- 위치/heading이 불안정하면 좌/우를 확정하지 않고 `천천히 주변을 비춰 방향을 확인하세요`로 보수적 안내하고, 전방 3D 화살표도 띄우지 않는다.
- 방향 구간: 정면(±20도) / 약간 좌·우(±55도) / 좌·우(±120도) / 뒤쪽 좌·우.
- 실내 재현: 디버그 패널 `정확도 저하 시뮬레이션` 토글(주입 정확도 30m) + 하단 지도 다중 탭(점프/경로 이탈)으로 검증. 상태는 `navigationStabilityDiagnostics`로 표시한다.

## 6. 회전 안내 UX 규칙

회전 안내는 실제 turn point 좌표에 오브젝트를 꽂지 않는다. 위치와 heading이 흔들리는 도심 환경에서 좌표 고정 화살표는 엉뚱한 도로/건물/인도 위에 보일 수 있기 때문이다.

대신 회전 안내는 다음 규칙으로 처리한다.

- TMAP route polyline에서 45도 이상 방향이 바뀌는 지점을 turn point로 계산한다.
- turn point 주변에 넓은 turn boundary를 둔다.
- 사용자의 현재 위치 점, 위치 오차 원, 경로 스냅 위치 중 하나라도 turn boundary에 들어오면 회전 안내를 활성화한다.
- 활성화된 화살표는 turn point 좌표가 아니라 카메라 로컬 좌표에 생성한다.
- 오른쪽 회전은 화면 오른쪽 전방, 왼쪽 회전은 화면 왼쪽 전방에 둔다.
- 화살표는 `실제 그 지점에 있는 물체`가 아니라 `지금 해야 할 행동을 알려주는 AR 안내`로 취급한다.
- 회전 완료는 다음 segment 방향으로 이동하기 시작했거나, turn point를 지나 일정 거리 이상 진행했거나, heading/이동 방향이 다음 경로와 정렬됐을 때로 판단한다.

카메라 로컬 기준 초기값은 다음과 같이 둔다.

```text
오른쪽 회전: x +1.0m, y 기기 높이, z -3.0m
왼쪽 회전: x -1.0m, y 기기 높이, z -3.0m
직진 유지: x 0.0m, y 기기 높이, z -3.0m
```

이 값은 시연 테스트에서 화면 가독성, 발열, 흔들림을 확인하며 조정한다.
