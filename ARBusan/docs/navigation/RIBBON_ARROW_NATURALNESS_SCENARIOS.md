# 리본·방향 화살표 "자연스러움" 시나리오 카탈로그

> 목적: 실사용 중 바닥 리본/회전 화살표/도착 핀이 **사용자 눈에 자연스럽게** 보이는지를
> 좌우하는 시나리오를 모아, 각 시나리오의 **증상 → 원인 → 해결안 → 실기기 테스트법 → 우선순위**를
> 한곳에서 관리한다. 현장 실측 전 체크리스트이자, 발견되는 어색함을 분류해 넣는 살아있는 문서.
>
> 관련 문서: [`TURN_UX_RULES_V2.md`](TURN_UX_RULES_V2.md)(회전 트리거·배치 규칙),
> [`AR_NAVIGATION_LOGIC_PLAN.md`](AR_NAVIGATION_LOGIC_PLAN.md)(위치/heading 불안정 로직).
>
> 코드 기준점: 리본 샘플 `RouteGeometry.forwardRibbonSamples`(`NavigationStabilizer.swift`),
> 리본 스냅샷 `AppState.navigationRibbonSnapshot`, 렌더 `ARSessionViewController.updateRibbonPlacement`,
> 주행 방향 앵커 `TravelDirectionAnchor`.

---

## 0. 자연스러움의 정의(합격 기준)

리본/화살표가 "자연스럽다"는 것은 다음을 만족하는 상태로 정의한다. 각 시나리오는 이 기준을 깨는 경우다.

1. **내 발 앞에서 시작** — 리본은 항상 사용자 정면 바닥에서 뻗어 나가야 한다(옆/뒤에서 시작 금지).
2. **도로 방향과 일치** — 리본이 실제 인도/도로 위로 깔리고, 진행 방향으로 흐른다.
3. **흔들리지 않음** — 멈춰 있거나 천천히 걸을 때 좌우로 "헤엄치지(swimming)" 않는다.
4. **튀지 않음** — 위치/heading 갱신 시 순간이동·깜빡임이 없다.
5. **정직함** — 신뢰할 수 없을 땐 강하게 그리지 않고 줄이거나 숨긴다(틀린 확신 금지).

## A. 리본 시작점 / 측면 정렬 (가장 시급)

### A-1. 리본이 옆에서 시작한다 ★최우선·보고됨
- **증상**: 굴곡진(비격자) 도심에서 리본이 내 정면이 아니라 **옆에서** 시작해 진행 방향으로 휘어 들어간다.
- **원인**: `forwardRibbonSamples`의 첫 점이 **현재 위치에서 경로선에 내린 수선의 발(최근접 투영점)**. TMAP 보행자 경로는 도로/인도 중심선을 따르고, GPS 오차+인도 폭 때문에 내 실제 위치는 경로선에서 3~10m 옆 → 최근접점이 정측면에 찍힌다. 곡선에선 최근접점 방위가 90°에 근접해 더 심함.
- **해결안**:
  1. **횡오프셋 재중심(snap-to-path, 클램프)**: 내→최근접점 횡벡터를 모든 샘플에서 빼 리본을 발밑으로 끌어온다. 곡률(점들의 상대 모양)은 보존, 위치만 보정. **최대 보정량 클램프**(예 6m)로 실제 이탈은 여전히 드러나게.
  2. **전방 콘 컬링 + 최소 리드**: 진행/시선 방향 기준 ±70° 콘 밖(옆/뒤) 샘플 제거, 첫 점을 최소 N미터(예 1.5~2m) 앞으로 밀어 정면에서 시작.
  3. 둘을 조합: 재중심으로 평행 오프셋 제거 → 콘 컬링으로 시작 각 정리.
- **테스트법**: 곡선 인도(예: 강변/공원 산책로, 휜 골목)에서 길찾기. 리본이 정면에서 시작하는지. 인도 가장자리에 붙어 서서(경로선에서 일부러 떨어져) 리본이 옆으로 밀리지 않는지.
- **우선순위**: P0.

### A-2. 리본이 뒤에서 시작/뒤로 뻗는다
- **증상**: 경로 최근접점이 사용자 뒤쪽이라 리본 첫 세그먼트가 뒤를 향하거나 발 뒤에서 시작.
- **원인**: 곡선 또는 경로 시작부에서 최근접 세그먼트가 진행 방향 뒤에 위치. 현재 전방/후방 구분이 없음(인덱스 증가 방향만 따름).
- **해결안**: 진행 방향(facing/movement bearing) 기준 **후방 샘플 컬링**. A-1의 전방 콘과 같은 메커니즘.
- **테스트법**: 경로 첫 지점 근처에서 목적지 반대쪽을 보고 섰다가 회전. 리본이 뒤로 깔리지 않는지.
- **우선순위**: P0(A-1과 동일 작업으로 해결).

### A-3. 직선 폴백 경로에서 리본이 부자연
- **증상**: TMAP 실패/키 없음 시 리본이 도로를 무시한 직선으로 깔림.
- **원인**: `fallbackNavigationRoute`가 `[현재위치, 목적지]` 직선. 곡률 정보 없음.
- **해결안**: 폴백 시 리본을 **짧게/약하게** 그리거나 텍스트 안내로 강등(직선 리본이 벽을 관통하는 오해 방지). 폴백임을 시각적으로 구분.
- **테스트법**: TMAP 키 제거 빌드 또는 네트워크 차단으로 폴백 유도.
- **우선순위**: P2.

## B. 방향(북)/heading 정렬

### B-1. 월드 북 미스캘리브레이션 → 리본 통째 회전 (구현됨 §4-C)
- **증상**: 리본/화살표가 도로가 아닌 벽 쪽으로 일정 각도 회전된 채 깔림.
- **원인**: `.gravityAndHeading` 세션 시작 시 자기 간섭으로 월드 북이 틀어져 고정.
- **해결안**: **(구현됨)** §4-C 감지(자동) + "방향 보정" 배지(수동 세션 재고정). → [`TURN_UX_RULES_V2.md`](TURN_UX_RULES_V2.md) §6.
- **테스트법**: 실내/금속 근처에서 세션 시작 후 실외에서 배지 노출·보정 동작 확인.
- **우선순위**: P0(완료, 실측 튜닝 남음).

### B-2. heading 흔들림 → 리본 좌우 "헤엄침(swimming)"
- **증상**: 멈춰 있거나 천천히 걸을 때 리본이 좌우로 미세하게 흔들린다.
- **원인**: 카메라 heading/나침반 노이즈가 매 프레임 bearing에 반영. 리본 길수록 끝단 진폭 큼(heading 10°→20m 끝 ~3.5m).
- **해결안**: heading **신뢰도 게이팅**(`facing.isConfident`)에 더해, (1) bearing **저역통과 스무딩**, (2) **리본 길이↔heading 신뢰도 연동**(불안정→짧게/숨김), (3) 정지 시 리본 **고정(hold)**.
- **테스트법**: 가만히 서서 폰만 미세하게 움직일 때 리본 흔들림 정도. 천천히 걸을 때.
- **우선순위**: P1.

### B-3. 정지 상태 facing 불확실
- **증상**: 서 있을 때 movement bearing이 없어 리본/화살표가 안 뜨거나 방향이 부정확.
- **원인**: `facingEstimate`가 이동 방향에 의존하는데 정지 시 신호 없음 → 카메라 heading만 사용.
- **해결안**: 정지 시 카메라 heading 가중, "방향 잡는 중" 보수 표시. 걷기 시작하면 movement bearing으로 보강.
- **테스트법**: 출발 직전 정지 상태에서의 표시.
- **우선순위**: P2.

## C. 위치 정확도 / 점프

### C-1. GPS 점프 → 리본 순간이동
- **증상**: 위치가 튀면 리본 전체가 순간이동.
- **원인**: origin 좌표 급변. `GuidanceFix`의 held/snapped로 일부 흡수하나 리본 재생성에 그대로 반영될 수 있음.
- **해결안**: origin 좌표 **스무딩/held** 적용 후 리본 생성. 큰 점프는 한 박자 무시.
- **테스트법**: 건물 사이/지하 입구 등 GPS 불안정 구간 보행.
- **우선순위**: P1.

### C-2. 저정확도 → 횡오프셋 과대
- **증상**: 정확도 나쁠 때 A-1(측면 시작)이 심해짐.
- **원인**: horizontalAccuracy 큼 → 최근접점 횡거리 큼.
- **해결안**: 정확도 나쁘면 리본 **짧게/숨김**, A-1 재중심 보정량을 정확도에 비례 제한.
- **테스트법**: 정확도 신호(품질 칩 §4-A) 보며 흐린 구간 비교.
- **우선순위**: P1.

### C-3. VPS↔GPS 소스 전환 시 튐
- **증상**: 위치 소스가 바뀌는 순간 리본이 갑자기 이동.
- **원인**: 두 소스의 좌표 기준 차이.
- **해결안**: 소스 전환 시 **블렌딩/짧은 hold**.
- **테스트법**: VPS 잡히는 구간 ↔ 안 잡히는 구간 경계 보행.
- **우선순위**: P2.

## D. 거리 / 스케일 / 고도

### D-1. 화살표 거리 비례 배치가 너무 멀거나 가깝다
- **증상**: 회전 화살표가 코앞 또는 너무 멀리.
- **원인**: 2.5~12m 클램프(`ARSessionViewController`)가 상황에 안 맞음.
- **해결안**: 거리 곡선 재튜닝, 회전 임박 시 별도 처리.
- **테스트법**: 다양한 회전 거리에서 화살표 위치 체감.
- **우선순위**: P2.

### D-2. 리본이 기기 높이 고정이라 오르막/내리막/계단에서 떠/잠김
- **증상**: 경사·계단·육교에서 리본이 공중에 뜨거나 바닥에 박힘.
- **원인**: `ribbonHeightOffset = -1.2` 고정(평지 가정).
- **해결안**: depth/평면 없이 정밀 보정은 어려움 → 경사 구간 리본 **약화**, 또는 피치 기반 근사 보정. 정직성 우선.
- **테스트법**: 계단·경사로 보행.
- **우선순위**: P2.

### D-3. 리본 길이가 heading 신뢰도에 연동 안 됨
- **증상**: 불안정해도 긴 리본 → 끝단이 도로를 벗어남.
- **원인**: 현재 길이 고정(최대 14m).
- **해결안**: B-2와 함께 길이↔신뢰도 연동.
- **우선순위**: P1.

## E. 곡률 / 교차로 표현

### E-1. 급커브에서 화살표+리본 중복/혼란
- **증상**: 큰 회전에서 화살표와 곡선 리본이 겹쳐 어수선.
- **원인/현황**: slight=리본 전담, hard=화살표(`isHardTurn`)로 일부 분리됨.
- **해결안**: 경계 케이스(중간 각도) 역할 명확화, 회전 직전 리본 페이드.
- **테스트법**: 90° 코너, 완만한 굽이 각각.
- **우선순위**: P2.

### E-2. 연속 갈림길/복잡 교차로
- **증상**: 짧은 간격 회전이 연달아 나오면 안내가 늦거나 엉킴.
- **원인**: 단일 다음 회전만 표현.
- **해결안**: 다음+그다음 단계 예고, 거리 카운트다운 강화.
- **우선순위**: P2.

---

## F. 시각 / 가독성 / 환경

### F-1. 주간 햇빛 가독성
- **증상**: 밝은 야외에서 파란 반투명 리본이 안 보임.
- **해결안**: 외곽선/대비/밝기 상향, 환경광 대응.
- **우선순위**: P1(실외 필수).

### F-2. 오클루전 없음 (사람·벽 관통)
- **증상**: 리본/화살표가 사람·벽 앞에 덮여 그려짐.
- **원인**: depth/mesh 미사용(발열 트레이드오프).
- **해결안**: 정직성↔발열 균형. 당장은 보류, 추후 depth 옵션.
- **우선순위**: P3.

### F-3. 트래킹 상실 강등 (구현됨 §4-B)
- **증상**: 트래킹 불안정 시 앵커 흔들림.
- **해결안**: **(구현됨)** `arTrackingLimited` 시 3D 숨김+텍스트 강등.
- **우선순위**: P0(완료).

## G. 상태 전환

### G-1. 경로 재탐색 중 리본 깜빡임 (부분 구현됨 §4-A)
- **증상**: 재탐색 시 리본이 사라졌다 다시 생김.
- **해결안**: **(구현됨)** `forceReroute` soft 유지(새 경로 도착까지 기존 안내 유지). 교체 순간 페이드 보강 여지.
- **우선순위**: P1.

### G-2. 도착 임박 리본→핀 전환
- **증상**: 도착 직전 리본과 핀이 어색하게 공존.
- **해결안**: 마지막 수 m에서 리본 페이드아웃 + 핀 강조, "입구/어느 쪽" 안내.
- **우선순위**: P2.

## 우선순위 요약

| 순위 | 시나리오 | 상태 |
|---|---|---|
| **P0** | A-1 측면 시작, A-2 후방 시작 | 미구현(다음 작업 후보) |
| P0 | B-1 북 미스캘리브레이션, F-3 트래킹 강등 | 구현 완료 |
| **P1** | B-2 헤엄침, C-1 점프, C-2 저정확도, D-3 길이연동, F-1 가독성, G-1 재탐색 깜빡임 | 일부 구현 |
| P2 | A-3, B-3, C-3, D-1, D-2, E-1, E-2, G-2 | 미구현 |
| P3 | F-2 오클루전 | 보류 |

**다음 작업 권장**: A-1/A-2(측면·후방 시작) 동시 해결 — `forwardRibbonSamples`에 전방 콘 컬링 + 횡오프셋 재중심(클램프)을 넣고, 순수 함수라 단위 테스트로 고정 가능. 이것이 "자연스러움" 체감에 가장 큰 레버.
