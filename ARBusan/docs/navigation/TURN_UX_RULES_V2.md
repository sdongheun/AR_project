# Turn UX 규칙 v2 (설계 제안)

현재 길찾기 회전/리본 규칙은 동작은 하지만 "기하학적 각도" 기반의 단순 휴리스틱이다. 실제 보행 UX를 만족하려면 더 정교한 규칙이 필요하다. 이 문서는 그 방향을 정리한 **제안(아직 미구현)**이며, 구현 기준 문서는 [`AR_NAVIGATION_LOGIC_PLAN.md`](AR_NAVIGATION_LOGIC_PLAN.md)다.

상태: 제안 / 단계 구현 대기. 다수 항목은 실외 실측으로 임계값을 튜닝해야 한다.

## 0. 관통 원칙

- **회전의 근거를 기하 각도가 아니라 TMAP 안내(turnType)로 바꾼다.** 정교함의 대부분이 여기서 나온다.
- AR은 "정확한 바닥 좌표"가 아니라 **방향 힌트**다. 신뢰 기준은 하단 2D 지도다(기존 MVP 원칙 유지).
- 표현 강도를 **heading/위치 신뢰도에 비례**시킨다(안정→강하게/길게, 불안정→약하게/숨김/텍스트).

## 1. 회전 판정: 각도 → TMAP 안내점

현재 `routeTurnMinimumAngleDegrees(45°)` 단일 임계값은 두 가지를 뭉뚱그린다: ① 길의 곡률 ② 갈림길 결정 복잡도. 그래서 한계가 명확하다.

- 1자 도로의 완만한 45° 굽이 → 안내 불필요한데 화살표가 뜸
- 30°짜리 Y자 갈림길 → 헷갈리는데 각도 미달로 안 뜸

**제안:** TMAP 보행자 경로 응답의 Point feature가 주는 `turnType`/`description`/`nextRoadName`을 회전 근거로 사용한다. 현재 `TMAPClient`는 Point를 도착 좌표로만 쓰고 이 정보를 버린다.

- TMAP maneuver가 있으면 그 지점을 회전으로 본다(완만한 곡선엔 maneuver가 없어 화살표 안 뜸 / 작은 각도 갈림길에도 maneuver가 있어 화살표 뜸).
- 기하 각도(45°)는 turnType이 없을 때의 **fallback**으로만 유지.
- `turnType`을 회전 종류로 매핑: 좌/우회전(큰 chevron), 좌측/우측 방향(약한 bear), 횡단보도·육교·지하보도·계단(보행자 전용 특수 안내).

작업 touchpoint: `TMAPClient`가 Point properties(turnType 등) 파싱 → 모델에 maneuver 배열 추가 → `routeArrowSnapshots`/리본이 maneuver 우선 사용.

> 구현 상태(1차): `TMAPClient`가 `turnType`을 파싱해 `TMAPRouteManeuver`/`TMAPManeuverKind`로 만들고(`route.maneuvers`), `routeArrowSnapshots`가 **turn maneuver를 우선** 사용한다(작은 각도 갈림길도 인정). maneuver가 없으면 기존 기하 45°로 fallback. 단위 테스트로 검증. 후속: 횡단보도/계단 등 특수 안내 표시, 거리 카운트다운(§2), 리본이 maneuver 활용.

## 2. 화살표 거리감 / 카운트다운

현재는 18m에서 준비하지만 화살표는 항상 전방 3m 고정이라 "얼마 남았는지"가 안 보인다.

- 화살표를 **실제 회전 거리에 비례**해 배치: `min(실제 회전 거리, 최대 ~10~12m)`, 가까워지면 화살표도 가까워짐. 너무 가까우면 하한 ~2.5m 클램프.
- **거리 라벨/카운트다운** 병기("15m 후 우회전"). maneuver를 쓰면 경로 누적 거리로 정확.
- 단계화: 멀면 예고(작게+텍스트), 가까우면(<~6m) 큰 확정 화살표.

> 구현 상태(1차): 화살표를 실제 회전 거리에 비례 배치(2.5~12m 클램프, `updateRouteArrowPlacement`)하고, `navigationTurnBanner`("Nm 후 좌/우회전")를 회전 화살표 활성 시 상단에 표시(`ARExploreView`). 거리는 현재 위치→회전 지점 직선 거리(경로 누적 거리 정밀화·단계 예고는 후속).

## 3. 바닥 리본 (길이 / 방향성 / 신뢰도 연동)

현재 리본은 다음 안내점까지 직선 1.2~6m라 짧고 방향 흐름이 없다.

- **길이**: 실제 경로 폴리라인을 따라 휘는 곡선 리본(15~20m, 보류했던 v2)으로.
- **방향성**: 리본 위로 흐르는 chevron/반복 화살표(저빈도 애니메이션, 발열 주의)로 직선에서도 방향 표시.
- **정직성 트레이드오프**: 리본은 heading 기반이라 길수록 끝단 오차가 커진다(heading 10° 오차 → 20m 끝 ~3.5m 이탈). 따라서 **리본 길이를 heading 신뢰도에 연동**(안정→길게, 흔들림→짧게/숨김).

### 3.1 곡선 직진 vs 결정 지점 (역할 분담)

길이 "완전히 꺾이는 것"이 아니라 "곡선으로 휘는 직진"인 경우는 **리본이 담당하고 화살표(chevron)는 띄우지 않는다.**

- **화살표 = 결정 지점(discrete)**: TMAP이 maneuver(turnType)를 찍는 곳에만(좌/우회전, 갈림길). 곡선 직진엔 TMAP이 maneuver를 안 찍으므로 화살표가 안 뜬다.
- **리본 = 길의 연속적 모양(continuous)**: 곡선의 휨을 폴리라인을 따라 그대로 보여준다. 곡선에 화살표를 띄우면 "꺾으라는 건가?" 하고 오히려 헷갈린다.
- v1 직선 리본은 곡선에서 **코너를 가로질러** 엉뚱한 방향을 가리키므로, 곡선 직진 처리가 바로 곡선 리본(v2)이 필요한 이유다.
- **약한 회전(slight, turnType 17·18) 처리 결정**: 완만한 굽이에서 TMAP이 "2시/10시 방향" 같은 약한 안내를 줄 때는 화살표 대신 **리본 전담**으로 표현하는 것을 검토한다. 즉 "강한 회전(12·13)·갈림길 = 화살표 / 약한 굽이 = 리본"으로 분리(현재 코드는 slight도 화살표로 매핑되어 있어, v2에서 조정 후보).

## 4. 실내/벽 배치 문제 (본질적)

정확한 실내 측위(VPS/실내지도)가 없으면 리본을 진짜 인도 위에 올릴 수 없다(네이버 레퍼런스의 전제 인프라). 실내에선 자기장 간섭으로 절대 북이 틀어져 리본이 벽 쪽에 깔릴 수 있다.

- **과장하지 않기**: "정확한 바닥 차선"이 아니라 방향 힌트로 다룬다. 살짝 띄운 방향 밴드가 바닥 페인트보다 오배치 시 덜 어색하다.
- **heading 신뢰도 게이팅 강화**: compass와 ARKit 상대 yaw의 발산을 감지해 불안정하면 리본 숨김 + 텍스트/2D 폴백 + "방향 보정 중" 안내.
- **갱신**: 리본 방위에 저역통과 필터(벽-벽 스윙 방지), 의미 있는 변화에만 갱신, 순간 튐엔 직전 양호값 유지.
- **결론**: 실내 정밀 리본은 MVP 범위 밖(부산 실외 관광지가 타깃). 실내는 "방향 참고 + 하단 2D 지도 신뢰"로 명시.

## 5. 촘촘한(예: ~5m 간격) 연속 회전

- 5m 간격 "회전"의 상당수는 진짜 회전이 아니라 TMAP 폴리라인이 곡선을 잘게 쪼갠 노이즈다 → 기하 각도 방식은 가짜 회전을 양산한다(또 maneuver를 써야 하는 이유. maneuver는 이미 이산 회전으로 병합돼 있음).
- 진짜 연속 회전(좌→즉시 우, 지그재그)이면: 가까운 회전을 윈도우(<~8m)로 **병합**하거나 "곧 좌회전, 그다음 우회전" **복합 안내**(임박 회전 크게 + "그다음 →" 미리보기).
- 곡선 리본(3번)이 깔리면 잔회전은 리본이 흡수 → 화살표는 진짜 결정점에만.

## 6. 놓치기 쉬운 추가 고려사항

- **경로 이탈 → 재탐색**: 경로선에서 일정 거리/시간 이상 벗어나면 TMAP 재요청. 현재는 "불안정" 표시만 하고 재탐색 없음(실제 내비 필수).
- **안전(중요)**: 카메라를 보며 걷게 만드는 건 위험. 음성/햅틱 우선("지금 우회전"), 화면은 흘끗 보조로.
- **트래킹 상실**: ARKit `trackingState == .limited`면 월드 앵커가 흔들림 → 3D 끄고 2D/텍스트로 강등.
- **세션 시작 시 북 초기화 함정**: `.gravityAndHeading`은 시작 순간 나침반으로 월드 북을 고정. 실내/금속 근처에서 켜면 세션 내내 월드가 틀어진 채 모든 게 어긋남 → 재보정(세션 재실행) 어포던스 필요.
- **GPS 첫 수신 워밍업**: 초반 수 초는 위치가 나쁨 → 정확도 안정 전 확정 안내 보류.
- **고도/경사**: 리본/화살표가 기기 높이 고정이라 오르막·계단·육교에서 어긋남.
- **주간 가독성**: 햇빛에서 파란 반투명이 안 보일 수 있음 → 외곽선/대비/밝기.
- **오클루전 없음**: depth/mesh 없이는 사람·벽 앞에 덮어 그려짐(정직성↔발열 트레이드오프).
- **도착 마무리**: 마지막 몇 m에서 "어느 쪽/입구" 안내 보강.

## 7. 우선순위 / 단계

1. ~~**TMAP turnType 안내점 도입**~~ (1차 구현 완료: 파싱 + 회전 소스 maneuver 우선, 기하 45° fallback. 거리 카운트다운·특수 안내·리본 활용은 후속) ← 다음 후속
2. ~~**거리 비례 배치 + 거리 라벨/카운트다운**~~ (1차 구현 완료: 화살표 거리 비례 배치 + "Nm 후 좌/우회전" 배너. 경로 누적 거리·단계 예고는 후속).
3. **heading 신뢰도 연동 리본 길이 + 곡선 리본 v2** (3·4).
4. **경로 이탈 재탐색**, 트래킹 상실/북 재보정 어포던스 (안전·견고성).

각 단계는 단위 테스트로 로직을 고정하고, 표현/배치는 실기기 실외 실측으로 튜닝한다.

## 8. 검증 필요(실측 의존)

- 거리 비례 배치의 최대/최소 거리, 라벨 노출 거리.
- 리본 길이↔heading 신뢰도 곡선, 곡선 리본의 끝단 허용 오차.
- 회전 병합 윈도우(~8m) 적정값.
- 실내 heading 발산 감지 임계값과 폴백 전환 타이밍.
