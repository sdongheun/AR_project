# ARBusan 화면 가장자리 마커 규칙

이 문서는 `ARBusan_AR_TECH_ROADMAP.md`의 `6.4.6 projection 기반 라벨 안정화` 중 `화면 밖/가장자리 처리` 규칙을 따로 정리하기 위한 문서다.

현재 목적은 구현 전 규칙 확정이다. 사용자가 현장 테스트에서 헷갈리지 않도록, 라벨과 가장자리 마커가 언제 보이고 숨겨지는지 먼저 정의한다.

## 1. 용어

- 실제 라벨: 사용자가 최종적으로 보는 관광지/건물 정보 라벨이다. 예: `투썸플레이스`, 거리, 신뢰도.
- matrix 마커: projection matrix 투영 위치를 확인하기 위한 개발용 디버그 마커다. 예: `matrix 4/13`.
- 가장자리 마커: 대상이 화면 밖에 있을 때 화면 가장자리에 붙어 방향만 알려주는 사용자용 마커다.
- 거리 반응형 라벨/마커: 같은 projection/edge marker 시스템을 사용하되, 사용자와 대상 사이의 거리에 따라 크기와 정보량을 다르게 표현하는 라벨/마커다.
- 화면 안 polygon: 대상 건물 polygon 외곽 좌표 중 하나 이상이 현재 화면 안에 투영된 상태다.
- 화면 밖 polygon: 대상 건물 polygon 외곽 좌표가 현재 화면 안에 하나도 투영되지 않은 상태다.
- 정반대 방향: 대상 방향과 현재 카메라 방향의 차이가 약 180도인 상태다.

## 2. 확정 규칙

### 2.1 화면 안에 polygon이 보이는 경우

- 실제 라벨을 표시한다.
- 실제 라벨은 projection matrix 좌표를 우선 사용한다.
- Scene Semantics는 점수에 반영하지 않고 라벨 위치 보정에만 사용한다.
- 가장자리 마커는 표시하지 않는다.

### 2.2 화면 안에 polygon이 보이지 않는 경우

- 실제 라벨은 숨긴다.
- 가장자리 마커만 표시한다.
- 가장자리 마커는 화면 테두리에 붙어서 “이 방향으로 돌리면 대상이 있다”는 힌트를 준다.
- 가장자리 마커는 짧은 이름만 표시한다. 예: `투썸`, `후참잘`, `해운대`.
- 가장자리 마커에는 MVP 단계에서 거리/상세 설명을 표시하지 않는다.

### 2.3 정반대 방향을 보는 경우

- 실제 라벨은 절대 화면 중앙에 표시하지 않는다.
- 가장자리 마커도 화면 중앙에 표시하지 않는다.
- 사용자가 어느 방향으로 돌아야 하는지 알 수 있도록 왼쪽 또는 오른쪽 가장자리에 붙인다.
- 왼쪽/오른쪽 선택은 대상 방향까지의 signed angle 기준으로 결정한다.
  - signed angle이 음수면 왼쪽 가장자리
  - signed angle이 양수면 오른쪽 가장자리
- 정확히 180도에 가까워 signed angle 방향이 불안정하면 마지막으로 안정적으로 계산된 방향을 유지한다.

### 2.4 여러 건물이 한 화면에 들어오는 경우

- 투썸/올리브영/후참잘처럼 가까운 후보가 여러 개 있을 때, 화면 안에 들어오는 건물 polygon이 2개 이상이면 각각의 마커가 존재해야 한다.
- 실제 정보 라벨은 한 번에 1개만 크게 표시한다.
- 크게 표시할 실제 정보 라벨은 화면 중앙에 가장 가까운 후보를 우선한다.
- 나머지 후보들은 짧은 이름 마커로 표시한다.
- 사용자가 짧은 이름 마커를 탭하면 해당 후보를 실제 정보 라벨로 승격한다.

### 2.5 가장자리 마커 표시 개수와 우선순위

- 가장자리 마커는 최대 3개까지만 표시한다.
- MVP 우선순위는 카메라 중앙 방향에 가까운 순서다.
- 가까운 음식점/상점이 원거리 관광지를 가릴 수 있는 문제는 추후 개선 이슈로 남긴다.
- 추후 개선 후보:
  - 관광지/음식점/상점 카테고리 필터
  - TourAPI 관광지 우선순위
  - 사용자 관심 카테고리 우선
  - 원거리 landmark 우선 모드
  - 화면 중앙 방향에 있는 원거리 POI 가중치

### 2.6 마커 겹침과 화면 가장자리 위치

- 같은 방향에 가장자리 마커가 겹치면 MVP에서는 세로로 쌓는다.
- 세로 쌓기로 UI가 지저분해지면 추후 `+N` 묶음 표시를 검토한다.
- 가장자리 마커는 좌/우/상/하 가장자리를 모두 사용할 수 있다.
- 화면 안 짧은 이름 마커는 탭할 수 있어야 하며, 탭하면 해당 후보가 실제 정보 라벨로 승격된다.

## 3. 거리 기준

사용자 위치에서 관광지/건물까지의 거리 기준은 일단 1km로 둔다.

### 3.1 근거리

- 기준: 1km 이하
- 목적: 실제 화면에 보이는 건물/관광지에 라벨을 붙이는 것
- 화면 안 polygon이 없으면 실제 라벨을 숨기고 가장자리 마커만 표시한다.
- 정반대 방향에서 실제 라벨이 다시 뜨면 안 된다.

### 3.2 중거리/원거리

- 기준: 1km 초과
- 목적: 사용자가 “이 관광지/건물이 저 멀리 존재한다”는 거리감을 이해하는 것
- 1km 초과 대상도 근거리와 동일한 projection/edge marker 시스템을 사용한다.
- 차이는 라벨/마커의 크기, 강조도, 정보량이다.
- 1km 초과 라벨에는 최소한 짧은 이름과 거리를 포함한다. 예: `해운대 1.5km`.
- 건물 외곽에 정확히 붙이는 것보다 방향과 거리 안내가 더 중요하다.
- 화면 밖이면 가장자리 마커를 사용해 회전 방향을 알려준다.
- MVP 거리별 크기:
  - 1km 이하: 100%
  - 1km 초과: 75~80%
- 추후 필요하면 `0~1km`, `1~3km`, `3km 이상`처럼 세분화한다.

## 4. MVP 규칙안

1. 1km 이하 후보는 근거리 규칙으로 처리한다.
2. 1km 초과 후보도 같은 projection/edge marker 시스템으로 처리하되 라벨/마커 크기를 줄인다.
3. 근거리에서 화면 안 polygon이 있으면 실제 라벨을 표시한다.
4. 근거리에서 화면 안 polygon이 없으면 실제 라벨은 숨기고 가장자리 마커를 표시한다.
5. 180도 반대 방향에서는 가장자리 마커만 표시하고 중앙 라벨은 금지한다.
6. 가장자리 마커는 짧은 이름만 표시한다.
7. 가장자리 마커는 최대 3개까지 표시한다.
8. 가장자리 마커 우선순위는 카메라 중앙 방향에 가까운 순서다.
9. 화면 안에 polygon이 2개 이상 들어오면 각 후보의 짧은 이름 마커를 표시한다.
10. 실제 정보 라벨은 한 번에 하나만 표시한다.
11. 여러 화면 안 후보 중 실제 정보 라벨은 화면 중앙에 가장 가까운 후보를 우선한다.
12. 1km 초과 라벨/마커는 짧은 이름과 거리를 포함해 거리감을 표현한다.

## 5. 확정된 질문

- 가장자리 마커 표시 방식: 짧은 이름만 표시
- 화면 안 다중 후보 표시 방식: 실제 정보 라벨 1개 + 나머지는 짧은 이름 마커
- 다중 후보 중 실제 정보 라벨 선택 기준: 화면 중앙에 가장 가까운 후보
- 가장자리 마커 최대 개수: 3개
- 가장자리 마커 우선순위: 카메라 중앙 방향에 가까운 순서
- 근거리/중거리 기준: 1km
- 정반대 방향에서 signed angle 불안정 시: 마지막으로 안정적으로 계산된 방향 유지
- 1km 초과 관광지/건물: 근거리와 같은 방식으로 표시하되 거리 반응형 크기/정보량 적용
- 화면 안 짧은 이름 마커: 탭하면 실제 정보 라벨로 승격
- 같은 방향에 가장자리 마커가 겹칠 때: 세로로 쌓기, 추후 `+N` 묶음 검토
- 가장자리 위치: 좌/우/상/하 모두 사용

## 6. 아직 결정해야 할 질문

- 1km 초과 라벨/마커의 정확한 축소 비율: 75% 또는 80%
- 1km 초과 라벨/마커에 방향 화살표도 포함할 것인지
- 근거리 라벨과 1km 초과 라벨이 동시에 있을 때 우선순위와 표시 개수
- 1km 초과 라벨/마커를 탭하면 상세 정보로 승격할 것인지
